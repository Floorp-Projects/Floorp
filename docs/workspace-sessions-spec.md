# ワークスペースのセッション・ブックマーク切り替え仕様

状態: 実装・自動検証済み v0.4 / 2026-10-23 / ネイティブ全体ビルド・実機検証は別途

対象: Floorp の通常ブラウザーウィンドウ。Windows・macOS・Linux を検討対象とする。

調査したソース: Floorp `edb99a7d`、`floorp-runtime.lock.json` が指定する Floorp-Runtime `1553b7b550dfe555684628d175e0c1701a785d0b`。

この文書は会話で合意した実装の仕様と検証状況を記録する。既存コンテナをセッションとして利用し、原則としてワークスペースの既定セッションを使い、別セッションは明示操作で選ぶ。ブックマークの表示先はセッションとは独立して指定する。実装・検証の範囲は末尾に記載する。全 OS の3本指入力を動作確認済みとは扱わない。

## 1. 目標と用語

ワークスペースを切り替えるだけで、タブ構成・ログイン環境・必要なブックマークを使い分けられるようにする。タブや入力中の内容を維持し、現在のログイン環境を判別できることを優先する。

次の二つの使い方を同時に満たす。

- 仕事・個人・顧客のアカウントを分け、ワークスペースを切り替えて使う。
- 同じ仕事用ログインを複数の案件で共有し、案件ごとのタブとブックマークだけを分ける。

「新しいワークスペース」と「新しいログイン環境」を同一操作とみなさない。ブックマークの表示範囲もセッションとは独立して指定する。

| 用語 | 意味 |
| --- | --- |
| ワークスペース | 作業ごとにタブをまとめる場所。独立したセキュリティ境界ではない。 |
| セッション | Cookie・サイトストレージなどを保持するログイン環境。既存の通常コンテナを使う。ブラウザー終了時のタブ復元とは別の概念。 |
| 既定セッション | そのワークスペースで、起点タブも個別指定もない新規タブを開く環境。 |
| タブのセッション | 個々のタブが実際に使用している環境。ワークスペースを移動しても自動変更しない。 |
| 標準 | `userContextId = 0` の環境。「標準（他の標準タブと共有）」と表示する。 |
| ブックマークの表示範囲 | 共通、または選択した一つ以上のワークスペース。URL へのアクセス許可や保存データの隔離とは別の設定。 |

初期版の保証は「独立した新規操作にはワークスペースの既定を使い、ページから派生する操作には起点タブのセッションを引き継ぐ」とする。別セッションを明示選択したタブや、移動・既存データによる例外も扱うため、「ワークスペース内の全タブが必ず同じセッション」とは表現しない。

### 需要調査から採用した判断

Floorp と Zen には既にワークスペースへのコンテナ指定がある。価値の中心は、新しい隔離方式の発明ではなく、作成・共有・現在地の表示・復元を一貫した操作にすることに置く。

公開投稿では、複数アカウントの使い分け、Arc からの移行時に設定方法が分からないこと、同じログインで複数の作業を整理したいことが確認できた。一方、完全なプロファイル分離を求める利用者もおり、この機能だけでその需要を満たすとは説明しない。検索結果や議論の参加人数から市場規模・移行人数は推定しない。

| 要望 | 仕様上の扱い |
| --- | --- |
| ログイン環境を切り替える | 既存コンテナを使い、作成・共有・タブ規則を整える。 |
| 案件ごとにブックマークを変える | フォルダーを選択した複数ワークスペースに表示できるようにする。 |
| 素早く切り替える | 全 OS のボタン・ショートカットを先に成立させ、サイドバー入力を追加する。 |
| 全 OS の3本指操作 | 並行調査し、受信と競合を実機確認した環境から試験提供する。 |
| パスワード・拡張のアカウントまで分ける | 同一プロファイルの機能では保証せず、完全分離が必要な用途では別プロファイルを使う。 |

## 2. 初期版の範囲

中核機能の実装対象:

- ワークスペース作成時のセッション新規作成・共有・選択。
- 既定セッションとタブの実セッションの表示。
- タブを開く経路、移動、既定変更、復元時のセッション規則。
- フォルダー単位のブックマーク表示範囲と、検索・保存・編集を含む一貫した扱い。
- 全 OS 共通のボタン・割り当て可能なショートカットによる切り替え。

サイドバー内の水平スワイプを追加段階、ネイティブ3本指入力を検証済み環境だけの試験段階とする。ジェスチャー入力にはプレビュー、確定、キャンセル、動きを減らす設定を含めるが、その完成を中核機能の提供条件にはしない。

| データ | 初期版での扱い |
| --- | --- |
| Cookie・サイトストレージ | セッションごとに分かれる。共有セッションを使うワークスペース同士では共有。 |
| タブ・選択状態 | ワークスペースごとに表示。実セッションと入力内容は維持。 |
| ブックマーク | 保存先は既存の Places のまま。ワークスペースごとに表示範囲を絞る。 |
| 閲覧履歴、内蔵パスワード、拡張機能 | 同じブラウザープロファイル内で共有。外部パスワード管理拡張の保管庫設定も変更しない。 |

ブックマークを隠しても、閲覧履歴、入力済み URL、開いているタブ、管理画面、拡張 API から同じ URL が見つかる場合がある。ブックマークの表示範囲を秘密情報の保護や別プロファイルと同等の隔離として説明しない。ログイン画面では、そのセッションと異なるアカウントの保存済みパスワードが候補になる場合もある。

Arc の Favorites の再現、タブの自動アーカイブ、Arc データの専用インポーター、ブラウザープロファイル全体の分離は、この変更の実装対象に含めない。既存の汎用ブックマークインポートは維持する。

## 3. セッションとワークスペースの作成

### 作成画面

ワークスペース名・アイコンとともに「ログイン環境」を選択する。

| 選択肢 | 動作 |
| --- | --- |
| 現在と同じログイン環境を使う | 初期選択。作成画面を開いたワークスペースの既定セッションを共有する。「仕事と共有」など実名を示す。 |
| 別のアカウント用に新しく作る | 空の通常コンテナを作成する。既存の Cookie・サイトストレージを引き継がない。名前の初期値はワークスペース名。 |
| ほかのログイン環境を選ぶ | 通常コンテナまたは標準を選ぶ。現在のワークスペースと異なる既存環境を再利用できる。 |

共有元は選択タブの実セッションではなく、現在のワークスペースの既定とする。例外タブを選択中でも共有元が変わらない。ワークスペースのない通常の初期状態では標準を示す。既定が欠損中の場合は共有を初期選択せず、有効な環境を選ぶまで確定できない。

同じセッションを選んだワークスペース同士では、一方でのログイン・ログアウトがもう一方にも影響することを選択時に説明する。「仕事の案件を増やす」と「別の仕事用アカウントを使う」の違いを短い例で示す。

作成画面に示したセッション ID を確保対象として保持し、画面を開いた後のワークスペース切り替えで勝手に変更しない。確定時に存在を再確認し、消えていれば再選択を求める。共有は同じセッション ID への参照であり、共有元ワークスペースへの追従設定ではない。後で共有元の既定を変えても、作成済みの別ワークスペースの既定は変わらない。

確定前にはコンテナもワークスペースも生成しない。確定後は、セッションの確保、既定 ID を含むワークスペースの保存、最初のタブの作成の順で処理する。最初のタブも正しいセッションで生成する。

作成に失敗した場合は、当該操作が追加したワークスペースの定義・並び順・未使用の初期タブを戻し、作成前のワークスペースと選択タブを維持する。失敗した操作だけが作成し、ほかの操作からも参照されていない空のコンテナは後始末する。既存コンテナは削除しない。

### 共有と名前

- セッション名・色・アイコンはコンテナの既存情報を使う。独自の同名データを別ストアへ複製しない。
- セッション名の変更は、そのセッションを共有する全ワークスペースに反映される。ワークスペース名は個別に変更できる。
- 初期版では、ワークスペースの複製を新設することは必須としない。将来追加する場合も、セッションの共有と新規作成を区別する。

### 既存利用者と移行時の導線

- 更新時にログイン環境や既存ブックマークを自動分類しない。既存の標準を使うワークスペースも維持する。
- 作成画面とワークスペース設定から、同じ「共有／新規／既存を選ぶ」の操作へ到達できるようにする。
- セッションを新しく作ってもログイン状態は移らないこと、保存済みパスワードは共通であることを説明する。新セッションへの自動ログインや Cookie のコピーは行わない。
- ブックマークの割り当ては任意の次の操作とし、作成のために既存データの移動や再ログインを必須にしない。

## 4. タブを開くときの規則

セッションは、ページの読み込みやブラウザー要素の生成に先立って決定する。`TabOpen` 後にタブの表示属性を変更する処理だけに依存しない。

| 操作 | 使用するセッション |
| --- | --- |
| 新規タブボタン、通常の新規タブコマンド | 対象ワークスペースの既定。 |
| アドレスバー、ブックマーク、コマンドパレットから新規タブで開く | 対象ワークスペースの既定。 |
| アドレスバー、ブックマーク、コマンドパレットから現在のタブへ移動する | 現在のタブの実セッションを維持。候補が履歴由来かブックマーク由来かで変えない。 |
| ページ内リンク、`target=_blank`、`window.open`、認証ポップアップ | 起点タブの実セッション。起点が例外タブでも維持する。 |
| タブの複製 | 元タブの実セッション。 |
| 「別ワークスペースで開く」 | 明示された移動先ワークスペースの既定。元タブは変更しない。 |
| 「別セッションで開く」 | 明示されたセッション。自動で別ワークスペースへ振り分けない。 |
| 外部アプリからの URL | 明示された対象ウィンドウ、または直近に利用した通常ウィンドウの現在のワークスペースの既定。通常ウィンドウがなければ通常の起動処理後の既定を使う。 |
| 再起動、閉じたタブを戻す、アーカイブ復元 | 各タブに保存された実セッション。ワークスペースの現在の既定で上書きしない。 |
| 独立した新しい通常ウィンドウ | プロファイルの既定ワークスペースを選択し、最初の Web タブからその既定セッションを使う。ブックマーク等から新規ウィンドウを作る独立操作も同じ規則。 |
| ページから開く新しいウィンドウ | 起点の実セッションを維持。通常ウィンドウでは既定ワークスペースへ所属させ、必要なら例外表示する。認証ポップアップ等の専用ウィンドウも起点を維持する。 |
| 閉じたウィンドウを戻す | 保存した選択ワークスペースと各タブの実セッションを使う。独立した新規ウィンドウの規則では上書きしない。 |

通常の新規操作での優先順位は、明示的なセッション指定、起点タブのセッション、対象ワークスペースの既定とする。復元は別経路として保存済みの ID を尊重する。

ブックマークの表示範囲はログイン先を指定しない。仕事と個人の両方に表示する URL も、開いた場所と上表の規則で処理する。管理画面から非表示ブックマークを開いても、元の表示先へ自動でワークスペースを切り替えない。例外タブから既定を使いたい場合は「このワークスペースのログイン環境で新規タブに開く」を明示操作として用意する。

`0` は標準の明示指定であり、未指定として扱わない。`undefined`・`null` は未指定、負数・非整数などの不正値はエラーとする。起点や明示指定を持たない通常の Web タブを追加する拡張操作にも既定を適用するが、拡張が明示したコンテナは維持する。

外部 URL を既存タブに開く設定では、そのタブの実セッションと、外部 URL の使用先セッションが一致する場合だけ再利用する。異なる場合は、ワークスペースの既定セッションで新規タブを作り、既存タブは変更しない。外部 URL の使用先を合わせるためにタブのコンテナを書き換えない。

外部要求の受け付け時に対象ウィンドウ・ワークスペース ID・使用先セッションを固定する。非同期処理中の選択変更では振り替えない。対象の消失やセッション欠損は読み込み前に検出して保留し、標準へ自動変更しない。

受け付け後に利用者が別のワークスペースやタブへ移動した場合、後の選択を維持し、確保したワークスペースへ背景で追加する。必要なら開いた場所を通知する。再利用候補の既存タブも受け付け時に確保し、現在も対象ワークスペースに属して再利用条件を満たす場合だけ使う。成立しなければ新規に追加する。完了時の選択タブを新たな再利用対象として拾わない。

ブラウザー内で起点を追跡できる OAuth などの認証では、ポップアップからコールバックまで起点のセッションを維持する。アクティブなワークスペースが途中で変わっても、認証先を別セッションに変更しない。起点情報を持たずに外部アプリから戻る URL は通常の外部 URL 規則に従い、元セッションへの自動振り分けは保証しない。

## 5. タブの移動と既定セッションの変更

### ワークスペース間のタブ移動

移動先の既定とタブの実セッションが同じ場合は、タブと入力内容をそのまま移動する。

異なる場合は、ドロップまたは移動操作の完了時に次を選択する。

| 選択肢 | 動作 |
| --- | --- |
| 元のセッションのまま移動 | 推奨する初期選択。タブと作業状態を維持し、移動先では例外タブとして表示する。 |
| 移動先のセッションで開く | 移動先に URL を新しいタブとして開く。元タブは元の場所に残す。 |
| キャンセル | 移動せず、元の状態を維持する。 |

別セッションへ開く場合、Cookie・サイトストレージ・入力値・セッション履歴をコピーしない。ピン留めなどの表示設定は引き継げるが、ログイン状態やフォーム入力の移送は行わない。複数タブの操作では同じ選択を対象全体へ適用し、失敗した対象を示す。元タブは失敗時も維持する。

`blob:` など元の環境に結びついた URL を別セッションで再オープンできない場合は、その選択肢を無効にして理由を表示する。元のセッションのまま移動する操作は引き続き利用できる。

既存の「コンテナで開き直す」は、この新しい移動選択肢と区別する。元タブを閉じる既存操作では、通常の未保存入力の確認を維持し、初期版で一括移動から暗黙に呼ばない。

### 既定セッションの変更

「新しく開くタブから適用」と表示し、既存タブは再作成しない。既存タブの実セッションが新しい既定と異なる場合は例外表示にする。

同じワークスペースの定義はプロファイル内の全ウィンドウで共有するため、この変更は各ウィンドウの今後の新規タブに適用する。選択中のワークスペースやタブはウィンドウごとに維持する。

## 6. 表示と他のブラウザー機能

- ワークスペースの表示には名前・アイコンと既定セッション名を使う。色だけで環境を識別させない。
- 選択中のタブについては、実際のセッションを既存のアドレスバー表示などで確認できるようにする。
- 既定と異なる通常タブにはセッション名のバッジを付け、選択中ページにも実セッション名を常時表示する。ピン留め・折り畳んだ縦型タブでは固定幅を維持する小マーカーとツールチップ・読み上げを使い、選択すると本文側の表示で実名を確認できる。子タブが同じ例外セッションを引き継いだ場合も同じ規則で表示する。
- ピン留めタブ、タブグループ、分割表示の各タブにも同じ規則を適用する。分割表示では、ペインごとの実セッションが判別できること。
- 非表示ワークスペースのページや通信・音声を、切り替えだけを理由に終了しない。
- 初期版の Web パネルは、既存のパネル固有のコンテナ設定を維持する。ワークスペース切り替えに自動追従させない。Web パネルから派生するページ操作は、そのパネルを起点として扱う。
- 通常のセッション選択一覧から、Floorp のプライベートコンテナを明示的に除外する。`getPublicIdentities()` の列挙だけで判定しない。既存のプライベート機能は、この永続セッション作成機能に統合しない。

## 7. ブックマークの表示範囲

### 保存と表示のモデル

ブックマーク本体は既存の Places に一つだけ保存する。フォルダーの表示範囲を「共通（すべてのワークスペース）」または「選択したワークスペース」に設定でき、後者は複数選択を認める。セッション単位の表示範囲と、ブックマーク一件ずつの独立設定は初期版に追加しない。

同じセッションを使う案件 A・案件 B に別のフォルダーを表示できる。別セッションの仕事・個人に同じ資料フォルダーを表示することもできる。セッションの変更・名前変更では表示範囲を変更しない。

例:

| フォルダー | 表示先 | ログイン環境への影響 |
| --- | --- | --- |
| 共通資料 | すべて | なし。新規で開いたワークスペースの既定を使う。 |
| 案件 A | 案件 A のみ | 案件 B と同じ仕事セッションでも表示を分けられる。 |
| 仕事の手続き | 案件 A・案件 B | 同じブックマークを共有し、編集も双方に反映する。 |
| 個人用 | 個人のみ | 個人セッションとは独立した表示設定。 |

- 設定を持たない既存・インポート済みフォルダーは、親の範囲を継承する。制限する祖先がなければ共通とする。更新だけで従来の表示や配置を変えない。
- 表示範囲を設定する対象は通常のフォルダー。Places のルート、ツールバー等の組み込みルート、タグ、検索クエリー自体には設定しない。ツールバー直下の一部だけを絞る場合は通常のフォルダーへまとめる。
- 規則は配下へ継承する。入れ子に複数の規則がある場合、実効範囲は祖先すべてと自身の制限の積集合とする。子から親の制限を広げない。画面では継承元と実効範囲を示し、空になる変更には保存前に説明を出す。
- 表示先はワークスペース ID で保持する。名称・URL・並び順を識別キーにしない。フォルダーも Places の GUID で識別し、ブックマークをワークスペース別に複製しない。
- 同じ項目を複数のワークスペースで表示しても、編集・削除は一つの実体に反映することを編集画面で示す。別の内容にしたい場合は通常のコピー操作で別項目を作る。

### 適用する画面と検索

| 画面・操作 | 適用する規則 |
| --- | --- |
| ツールバーとオーバーフロー、ブックマークメニュー、サイドバーとその検索 | 操作先ウィンドウの現在のワークスペースで見える項目だけを表示。非表示項目をキー操作で選べる状態にしない。 |
| コマンドパレットの検索・ブックマーク切り替え・ページ送り | 同じ範囲。非表示項目を除外してから URL 重複除去と件数制限を行う。 |
| アドレスバーの候補、自動補完、ブックマークキーワード、ブックマーク由来のラベルと星 | 同じ範囲。同一 URL に複数の項目がある場合も、可視項目だけをブックマークとして扱う。 |
| フォルダーの「すべて開く」、検索クエリーフォルダーの結果 | 表示対象の子孫を評価してから開く。隠れた子孫を裏で開かない。 |
| ブックマーク管理画面 | 「すべてのワークスペース」を明示した全件表示。現在の表示先で絞る機能と、表示範囲の編集・未割り当ての確認を提供する。 |
| 拡張の bookmarks API、従来の全件エクスポート | プロファイル全体を扱う既存の動作。表示範囲によるアクセス制限は追加しない。 |

同じ URL のブックマークが非表示でも、履歴として独立に一致すれば候補に出してよい。可視ブックマークがない URL では履歴側の名前を使い、ブックマーク固有の名前、キーワード、一致判定、星、候補種別を持ち込まない。未訪問の非表示ブックマークだけを根拠とする候補・自動補完は出さない。

タグとブックマークキーワードの保存自体は、既存の URL 単位で共通とする。その URL に現在可視のブックマークがある場合だけ検索・キーワード解決へ利用する。同 URL に可視・不可視の両方がある場合は、共有のタグ・キーワードを利用できる。これらの由来をブックマーク一件ずつやワークスペース別に分離したとは説明しない。候補のブックマーク名は引き続き可視 GUID の項目から選ぶ。

保存済みの履歴スコアと、その過去のブックマークによる影響はプロファイルで共有し、ワークスペースごとに再計算しない。履歴の順位まで分離したとは保証しない。可視判定により、候補としての資格と、その場で付けるブックマークの情報を制御する。

結果を後から DOM/CSS で隠すだけでは不可とする。検索の一致判定・メタデータ選択・並べ替え・件数制限と、実際に開く対象を揃える。URL バーの後段で `BOOKMARKS` の候補だけを落とす実装も、履歴候補に名前等が混入するため不十分。

新規タブ画面やウィジェット等にブックマーク専用の表示がある場合も対象を洗い出して同じ判定へ接続する。履歴から生成する「よく見るサイト」をブックマーク表示と呼ばず、その履歴機能は既存の規則を維持する。macOS のネイティブメニューを含む適用漏れは公開前に確認する。

### 保存、星、編集、移動

- 通常の保存画面は保存先フォルダーとその実効範囲を示す。初回は既存の保存先を維持し、明示しないまま専用フォルダーへ移さない。
- 「このワークスペース用のフォルダーに保存」を選べるようにする。対応する既存フォルダーがなければ、確定時に通常のフォルダーを作り、現在のワークスペースだけの規則を付ける。作成画面を開いただけでは生成しない。
- 保存・編集・削除の開始時にもウィンドウ、ワークスペース ID、対象／保存先 GUID を保持する。切り替えや、対象が不可視になる範囲変更があれば通常画面のパネルを閉じ、未確定の操作をキャンセルする。既に確定した保存を勝手に取り消さない。書き込み直前にも対象と実効範囲を再検証し、確認時と異なる内容を別の対象へ適用しない。ワークスペースのない画面では「このワークスペース用」は選べない。
- 保存先の記憶はウィンドウ／ワークスペースの文脈を持たせる。記憶したフォルダーが削除済み、または現在非表示なら勝手にそこへ保存せず、共通の保存先を示して選び直せるようにする。
- 星は、現在可視のブックマークが同じ URL に一つ以上ある場合だけ点灯する。隠れた同 URL しかない場合は、現在の保存先へ新しい項目を追加できる。
- 星からの編集・削除は可視の指定 GUID だけを対象とする。複数ある場合は保存先と対象件数を示して選べるようにし、同 URL の不可視項目を巻き込まない。全件管理からの明示操作は別扱いとする。
- 組み込み UI での移動・コピーは、変更後の実効範囲を示す。制限のある親から共通へ出す等、見えるワークスペースが増える操作は確定前に確認できるようにする。移動は同じ GUID の規則を維持し、コピーは子孫も含む新旧 GUID の対応から明示規則を複製して、移動先の祖先制限を適用する。
- 通常画面でフォルダーを削除する際、配下に現在非表示の項目があれば、削除に含まれる件数も確定前に示す。表示中のフォルダーの削除が、見えない子孫も削除することを隠さない。
- 通常の Undo では、同じ GUID と表示範囲も戻す。新規作成やコピーが途中で失敗した場合、規則のない項目だけが共通で残らないようにする。
- 拡張や Sync からの変更も観測して表示を更新する。外部操作を追加の確認で止めることはしないが、新 GUID に名前や URL だけで古い規則を割り当てない。既存フォルダーへ追加された項目は、その祖先の規則を継承する。

### 切り替えと利用不能時

- 判定に使うのは対象ウィンドウの選択ワークスペースであり、選択タブの実セッションではない。例外タブや通常ウィンドウ内のプライベートコンテナを選んでも、表示範囲は変えない。
- ジェスチャーのプレビュー中は現在の表示を維持する。確定時に範囲を切り替え、旧範囲のメニューと検索候補を閉じるか再評価する。検索文字列は維持してよい。
- 検索の開始時にウィンドウ・ワークスペース ID・規則の世代を持たせる。切り替え、規則変更、Places の変更後に届いた古い結果は表示しない。クリックや一括で開く直前にも対象 GUID と有効範囲を再評価する。
- まだワークスペースが選択されていない起動中の画面と、ワークスペースを持たないプライベートウィンドウでは、共通の項目だけを表示する。別の通常ウィンドウの選択を借用しない。明示した全件管理は利用できる。
- ワークスペース機能または表示範囲機能を無効化すると、通常の全件表示へ戻す。この変化を無効化の画面で示し、規則自体は保持する。再有効化時にブックマークを移動・複製しない。
- 読み込み中は範囲付き項目を先に全件表示しない。既に有効化済みの規則が欠損・破損して読めない場合は、通常のブックマーク表示を保留し、復旧または明示的な制限解除へ案内する。全件管理から元データを確認できるようにし、自動で空の規則に置換しない。

### 削除、アーカイブ、同期、バックアップ

- ワークスペースを削除してもブックマークと表示規則は削除せず、共通にも変更しない。残る表示先でのみ見せ、表示先がなくなったものは管理画面で「表示先なし」として再割り当てできるようにする。消えた ID の参照は履歴として保持する。
- アーカイブでも同じ規則を適用する。同じプロファイルでそのアーカイブを復元する際は、元のワークスペース ID への参照だけを復元後の ID へ結び直す。現在の別の表示先や、アーカイブ後に利用者が行った範囲編集は上書きしない。元 ID の既存ワークスペースと衝突する場合は自動で結び直さない。
- フォルダー削除後も GUID の規則を直ちに破棄せず、Undo や同一 GUID の復元で戻せるようにする。GUID の正規化等に確定した対応関係がある場合だけ規則を引き継ぐ。異なる GUID を同じ名前・URL で推測して結び直さない。
- ブックマーク本体は既存 Sync の対象のまま。初期版では表示規則とワークスペース定義の新しい端末間同期を実装しない。設定時に「表示先はこの端末の設定。ブックマーク自体は通常どおり同期される」と説明する。別プロファイル・端末では未設定のブックマークが共通表示になる場合がある。
- 通常の HTML エクスポート／インポートや Places のブックマークバックアップだけでは、表示規則を移送できると保証しない。新しい GUID でのインポートは親の規則を継承する。
- 表示範囲機能の正式提供までに、規則と参照先ワークスペース情報を保存・復元できる Floorp 用の設定バックアップを用意する。ブックマーク本体や Cookie・パスワードを代替保存する形式にはしない。本体のバックアップと合わせて利用することを示す。
- 設定の取り込みは差分・一致しない GUID／ワークスペースを事前表示し、適用先を確定してから保存する。名前や URL の一致だけで自動対応しない。無効なデータや解決できない参照は報告し、現在の規則を消さない。既存の Places 復元で規則が参照する GUID が消えた場合も、勝手に全件共有へ書き直さない。

## 8. 削除、欠損、移行、復元

- ワークスペースの削除・アーカイブではセッションを自動削除しない。同じセッションを別のタブ・ウィンドウ・ワークスペース・Web パネル・アーカイブが参照する可能性がある。
- 初期版では、別の通常ウィンドウで対象ワークスペースが選択中、またはそのワークスペースに属するタブが存在する場合、削除・アーカイブを開始せず、利用中のウィンドウを案内する。非表示タブと復元保留中のタブも利用中として扱う。呼び出し元だけをアーカイブして共有定義を削除する動作は認めない。処理開始後に利用状況が変わった場合も、共有定義を削除する前に再確認して中止する。
- 初期版ではワークスペース画面に「セッションも削除」を追加しない。セッション削除は独立したコンテナ管理操作とする。名前変更・一覧などは既存管理機能へ接続する。
- 拡張や管理操作によって参照先が消えた場合は「セッションが見つかりません」と表示する。自動で標準へ読み込ませたり、同名の別セッションへ結び直したりしない。
- 欠損した既定を必要とする新規操作は読み込み前に保留する。有効な実セッションを使う既存タブの現在タブ移動や、そのタブを起点とする操作まで止めない。
- 欠損セッションを参照する復元タブは、ページ読み込み前に保留する。元の復元データを保持したまま、既存セッションへの割り当てか新規作成を選べるようにする。異なるセッションへの割り当てでは URL の再オープンを行い、フォーム値や履歴などの旧セッション状態は投入しない。
- 欠損セッションの復旧は、選択したワークスペース内の旧セッション ID ごとに行う。復旧画面で対象のワークスペースと保留タブ数を示し、確認した旧 ID→復旧先 ID を、そのワークスペースの既定（旧 ID と一致する場合）と、全通常ウィンドウの同じワークスペースに属する復元保留タブ（旧 ID と一致するもの）へ一貫して適用する。有効な別セッションのタブや読み込み済みタブの実セッションは変更しない。対象外のワークスペースと既存アーカイブは自動更新せず、それらの復元時に改めて割り当てを選ぶ。
- 更新時に既存タブを開き直さない。現在のワークスペース ID・既定 ID・タブごとの実セッションを維持し、既存の混在タブには表示のみ追加する。
- 新規作成 UI の初期選択は、既存 API の互換動作と分ける。既存の `createWorkspace(name)` 相当の呼び出しに、暗黙のコンテナ新規作成を追加しない。
- ID は同じプロファイル内の参照として扱う。他プロファイルや他端末へ数値 ID をそのまま流用する同期・インポート機能は追加しない。

## 9. ワークスペースを切り替える操作

### 全 OS 共通の動作

- ボタン、ショートカット、ジェスチャーは、対象ウィンドウと移動先 ID を指定する共通処理へ接続する。
- ワークスペースの並び順と、左右の移動先を一致させる。指で左へ払うと右隣、右へ払うと左隣へ移る。
- ジェスチャーでは端を越えて循環せず、端で短く戻る表示をする。既存の次／前ショートカットや API の循環動作は互換性のため維持する。
- OS のジェスチャーをキー入力へ変換する場合に備え、「次のワークスペースへ（端で停止）」「前のワークスペースへ（端で停止）」を別の割り当て可能なアクションとして追加する。内部 ID は `floorp-workspace-next-no-wrap` と `floorp-workspace-previous-no-wrap` とし、既存の `gecko-workspace-next`・`gecko-workspace-previous` の循環動作は変更しない。
- 全 OS 共通の新しい既定キーは、この仕様では決めない。既存のユーザー割り当てを維持し、次／前のアクションを設定画面から割り当てられるようにする。
- 切り替えの確定時にだけ既存のワークスペース変更処理を呼び、直前に選んでいたタブへ戻る。

### ジェスチャーの進行

開始時に対象ウィンドウ・現在のワークスペース・移動先を確定し、入力中のプレビューと実際の切り替えを分ける。

| 状態 | 動作 |
| --- | --- |
| 待機 | 他の入力を処理する通常状態。 |
| プレビュー | 移動先の名前・セッション名と、取得できる移動量に応じた表示を出す。現在のタブ・ブックマーク・検索範囲・フォーカスを維持し、移動先のブックマークやページを先取りしない。 |
| 確定 | 1回だけ移動先に切り替える。 |
| キャンセル | 表示を戻し、実際のワークスペースやタブを変更しない。 |

連続した移動量が取得できる入力だけ、指に追従するプレビューを使う。方向だけ届く入力や OS からのショートカットでは、確定後の短いアニメーションとする。実際には取得していない移動量を模擬して「指に追従する」と説明しない。

開始／終了と慣性を識別できる直接入力では、1回のジェスチャーで最大1ワークスペース移動する。終了時の移動量と速度で確定し、途中のしきい値通過だけでは確定しない。逆戻りや Esc でキャンセルできるようにする。慣性入力による連続切り替えを抑止する。移動量や速度の確定しきい値は、OS アダプターごとに実機評価して決める。

確定直前にウィンドウ、開始時の現在 ID、移動先 ID、機能の有効状態を再確認する。開始時の対象が成立しなくなっていればキャンセルする。

ウィンドウの非アクティブ化、タブのドラッグ開始、ワークスペースの削除・並べ替え、移動先の既定セッション変更、機能の無効化、別操作による切り替えでプレビューをキャンセルする。ワークスペースが1個以下の場合は入力を消費しない。

動きを減らす設定ではスライドを省略する。確定時のワークスペース名・セッション名は読み上げ可能にし、プレビュー中は読み上げを連続発火させない。

### 入力方法と競合

「3本指で切り替え」と「サイドバー内の水平スワイプ」を別の入力設定にする。

- 3本指の直接対応は、ネイティブ入力が3本指であることを識別でき、OS 操作との競合も確認できた環境でのみ有効にする。
- 指本数が不明な `wheel` や `MozSwipeGesture` を、3本指として推定しない。
- 一つの物理入力を複数の入力経路で重複処理しない。重複を識別・抑止できない環境では、競合する直接入力とサイドバー水平入力を同時に有効にしない。OS のキー変換と直接入力を同じ物理操作へ重ねる設定も案内しない。
- サイドバー内の水平スワイプは、ブラウザー UI のタブ／ワークスペース領域で開始し、水平の意図が確定した操作だけを使う。Web パネル内のコンテンツ、ポップアップ、編集中の入力欄、横スクロールを必要とする UI は除外する。領域外から移動してきた操作は拾わない。設定の初期状態はオフ。意図確定前の縦スクロール・ピンチ・ドラッグを維持する。
- 通常の Web コンテンツ上の横スクロールや履歴の戻る／進むを、水平スワイプ設定だけで置き換えない。
- OS が予約した操作を Floorp から自動変更しない。OS 側でキー割り当てを使える環境では、利用者が設定したショートカットを代替入力として使える。この用途では上記の「端で停止」アクションへ割り当て、ネイティブジェスチャーと同じ端停止の動作にする。通常のキー入力との区別は行わず、これらのアクションはキーで直接実行しても循環しない。
- キー変換では物理ジェスチャーの区切りと慣性を Floorp が取得できない。端停止は保証するが、変換元が複数のキー入力を送る場合に「1回の物理操作で1移動」とは保証しない。対応が確認できた環境には、1回の操作で1回だけキー入力を送る設定を案内する。

## 10. OS 別の対応方針

全 OS の調査・設計を並行して進める。共通機能の提供と、ネイティブ3本指対応の提供条件を分ける。

| OS | コードで確認した現状 | 3本指対応を有効にする条件 |
| --- | --- | --- |
| macOS | `swipeWithEvent` からスワイプ方向を送る経路がある。共通イベントには指本数を渡していない。 | 指本数または3本指専用の入力を識別する経路、OS のデスクトップ操作との関係を実機確認する。連続量が取れない経路は確定操作のみとする。 |
| Windows | Direct Manipulation の移動量・フェーズを扱う経路がある。確認した経路に指本数は含まれない。 | Precision Touchpad など対象機器・ドライバーで、アプリが3本指入力を受け取れる条件を確認する。OS のアプリ切り替えと競合しないことを確認する。 |
| Linux | GTK のコードに、タッチパッドのスワイプイベントを現在処理していないという記述がある。 | ランタイムでのイベント受信と指本数の受け渡しを追加し、Wayland／X11、GNOME／KDE 等で受信可能な組み合わせを確認する。 |

ネイティブ3本指対応は、検証済みの環境を明記した試験機能として、初期状態はオフで提供する。設定上も「ネイティブ入力に対応」「OS 設定でキー割り当て可能」「未検証」「直接対応なし」を区別し、未検証の設定を動作確認済みとして案内しない。ボタンとショートカットは全 OS 共通の正式機能として扱う。

ネイティブ側の変更が必要な場合、プリビルド済みランタイムへのソースパッチ適用だけでは提供できない。対応するネイティブ成果物の再ビルド・配布を実装計画に含める。

## 11. 実装構成と互換性

- セッションの実体は `ContextualIdentityService`、ワークスペースの参照は既存の `userContextId` を使う。別の資格情報ストアや二重のセッション ID を新設しない。
- セッションの確保・存在確認と、各タブ生成経路の決定規則を共通化する。ウィンドウを明示し、別のウィンドウのワークスペース設定を誤って参照しない。
- ワークスペース機能が無効な間は、保存済みのワークスペースの既定を新規タブに適用しない。起点も明示指定もない独立した新規操作は標準を使い、起点のある操作・明示指定・既存タブの実セッションは維持する。再有効化時も既存タブを開き直さない。無効中に作成され所属情報を持たないタブは、有効化時に選択されるワークスペースへ所属させ、実セッションは変更しない。
- ジェスチャーの共通コントローラーは、対象ウィンドウ、操作 ID、入力元、開始／更新／確定／キャンセル、方向、取得できる場合の進行量・指本数、慣性の有無を受け取る。
- OS 別アダプターは入力情報と対応能力を通知する。ワークスペースの生成・セッション変更・ページ再読み込みを担当させない。
- 既存のワークスペースの並び順、選択タブの記録、アーカイブを再利用する。データ形式の変更が必要になった場合は既存フィールドを保持する移行を設ける。
- ブックマーク規則は `schemaVersion` と、フォルダー GUID → ワークスペース ID 集合を持つ Floorp 固有のプロファイル内ストアとして保存する。既存 Places のスキーマと Sync レコードへ、未対応のフィールドを暗黙に追加しない。空集合、欠損参照、読み込みエラーを「共通」と区別する。
- 可視性の共通サービスはウィンドウ・ワークスペース ID・規則の世代と Places の項目 ID／GUID を受け取り、各表示・検索・操作経路が同じ意味で利用する。URL だけを渡してブックマーク一件の可視性を判断しない。同じ URL の可視 GUID を別途列挙できるようにする。
- 範囲規則の保存、フォルダー作成・コピー、Undo、アーカイブ復元での参照変更は、部分失敗や再起動で意図しない共通表示が残らないように回復可能にする。最後の有効な規則を保持する。規則変更の確定後に全ウィンドウの該当表示を無効化するが、他ウィンドウの選択は変えない。
- ランタイムの変更は Floorp 側の所定のパッチ管理に従う。兄弟の Floorp-Runtime チェックアウトを直接編集して実装を維持しない。

## 12. 受け入れ条件

実装時には、次の利用者の動作をブラウザー内テストと実機で確認する。自動検証の結果と実機未検証の範囲は末尾の実装状況に記録する。ログイン環境の検証には管理下のテストサイトと独立した Cookie 認証を使い、サイト側が行うアカウント全体のログアウト・失効処理とは区別する。

| 対象 | 合格条件 |
| --- | --- |
| ログイン環境 | 同じテストサイトを異なるセッションで開き、Cookie・localStorage・IndexedDB で別の値を保持する。一方の Cookie・サイトデータの削除が、もう一方の保存値と Cookie 認証状態へ波及しない。 |
| セッション共有 | 同じセッションを使う二つのワークスペースは、同じログイン状態を使用する。 |
| 新規作成 | 例外タブを選択中でも作成元ワークスペースの既定を初期選択し、最初の Web タブから確定したセッションを使う。画面を開いた後の選択変更で共有先が変わらず、キャンセルや失敗で空のワークスペース・未使用コンテナが残らない。 |
| 共有の独立性 | A・B が仕事セッションを共有した後、A の既定を変えても B の既定と両者のブックマーク範囲は変わらない。セッション名の変更は同じ ID の表示へ反映する。 |
| 開く経路 | 新規タブ、ブックマーク、外部 URL、明示指定 `0`、拡張による明示指定が決定規則どおりに動く。外部 URL の既存タブ再利用設定でも、異なるセッションのタブを書き換えない。 |
| 現在のタブ | 例外タブにブックマーク・URL 候補を現在タブで開いても実セッションを維持し、新規で開く場合は既定を使う。同じ URL を仕事・個人に表示しても、新規起動先はそれぞれの既定になる。 |
| 外部要求の競合 | URL を受け付けた後にワークスペースを切り替えても対象が変わらず、元の対象へ背景追加し、後の選択を奪わない。確保したセッションが消えた場合はページを標準で開かない。 |
| 新規・復元ウィンドウ | 独立作成は既定ワークスペース、ページからの作成は起点の実セッション、復元は保存済みの選択と実セッションを使い、最初の Web 読み込み前に決まる。 |
| 認証 | 起点を追跡できるブラウザー内フローでは、別ワークスペースへ切り替えた後も、起点のポップアップと OAuth コールバックが元のセッションに残る。起点情報のない外部 URL は通常の外部 URL 規則に従う。 |
| 移動・既定変更 | 元のセッションのまま移動したタブの入力内容を保持し、例外表示する。別セッションで開く場合も元タブを維持する。既定変更で既存タブが開き直されない。 |
| 復元 | 再起動、閉じたタブの復元、アーカイブ復元でタブごとの実セッションと選択タブを維持する。 |
| 欠損 | 削除されたセッションの URL を標準で自動読み込みしない。利用者が新しい割り当てを選ぶまでデータを保持する。同じ旧 ID の複数の保留タブと対象ワークスペースの既定を復旧先へ揃え、直後の新規タブも復旧先で開く。対象外のワークスペース・アーカイブは変更しない。 |
| 欠損中の既存タブ | 既定セッションの欠損中でも、有効な別セッションの既存タブの現在タブ移動・派生操作は、その実セッションで動作する。 |
| 削除・アーカイブ | 別ウィンドウに同じワークスペースの選択・非表示タブ・復元保留タブがある場合、呼び出し元だけを処理して共有定義を削除しない。操作を中止し、他ウィンドウのタブを維持する。 |
| 無効化・再有効化 | 無効中の独立した新規タブは標準を使い、起点・明示指定は維持する。無効化と再有効化で既存タブの実セッション・入力内容を変えず、所属情報のないタブを例外表示も含めて正しく再表示する。 |
| 互換性 | 既存の混在タブ、ピン留め、タブグループ、分割表示、Web パネル、プライベートコンテナの既存用途を維持する。 |
| 操作 | 区切りと慣性を識別できる直接入力では1ジェスチャーで最大1回移動し、慣性で再移動しない。途中の逆戻り・Esc・非アクティブ化でキャンセルし、タブ・フォーカス・表示範囲が変わらない。ボタン・キー・直接入力で同じ移動先の最終状態が一致する。 |
| OS のキー変換 | OS の3本指操作を「端で停止」アクションのキーへ割り当てた場合、先頭・末尾を越えて循環しない。既存の次／前アクションに割り当てた通常のキーは従来どおり循環する。 |
| ウィンドウ | 操作したウィンドウだけが切り替わる。共有セッションの変更は反映されても、他のウィンドウの選択は変わらない。 |
| 入力の競合 | ページの縦横スクロール、履歴操作、ピンチ、タブのドラッグと誤発火しない。 |
| 入力経路の重複 | 同じ直接入力がサイドバー入力とネイティブの両方から届いても二重に切り替わらない。識別できない組み合わせは同時に有効化されない。 |
| アクセシビリティ | キーボードとマウスだけで全操作ができる。色を見分けなくてもセッションを識別でき、動きを減らす設定と読み上げが機能する。 |

ブックマーク表示範囲には、さらに以下を必須とする。

| 対象 | 合格条件 |
| --- | --- |
| 既存データ | 更新後も未指定のブックマークの配置・GUID・全体表示が変わらず、コピーが生成されない。 |
| 表示の独立性 | 同じセッションの案件 A・B で別フォルダーを表示でき、両方だけに共有するフォルダーも指定できる。既定セッションを変更しても範囲は変わらない。 |
| 入れ子・移動 | 親 A、子 A・B の実効範囲は A のみ。共通へ移す等で範囲が広がる場合は事前に分かり、コピー・Undo・途中失敗でも規則を失わない。 |
| 表示経路 | ツールバー、オーバーフロー、メニュー、サイドバー、検索、パレット、URL バー、星、キーワード、クエリー結果、一括で開く操作が同じ範囲を使う。キー操作でも不可視項目を開けない。 |
| 同じ URL の複数項目 | A 専用の名前と B 専用の名前を持つ同 URL を作り、それぞれ可視の名前で表示する。不可視項目が URL 重複除去や件数制限で可視項目を押し出さない。 |
| 履歴との境界 | 未訪問の不可視ブックマークだけを根拠とする補完は出ない。可視ブックマークのない URL は履歴の一致条件・名前で表示でき、ブックマークの名前・タグ・キーワード・星は混入しない。同 URL に可視項目がある場合の共有タグ／キーワードと、保存済みの履歴スコアは維持する。 |
| 保存・削除 | 他のワークスペースに同 URL があっても現在の保存先へ追加できる。星から一つを削除しても不可視の同 URL は残る。共有項目の編集が他の表示先にも反映することを確認できる。 |
| 保存中の切り替え | A で開いた未確定の保存／編集パネルは B へ切り替えると閉じる。別ウィンドウで保存先が不可視になった場合も、古いパネルから保存・削除を実行しない。 |
| 削除・アーカイブ | ワークスペースを削除・アーカイブしても本体は残り、共通表示へ変化しない。表示先なしは管理画面で回復でき、アーカイブ復元で対象 ID の参照だけが正しく引き継がれる。 |
| 同期・バックアップ | 本体の Sync と表示規則のローカル保存を区別できる。設定バックアップと本体の復元で一致した参照だけを復旧し、未解決・無効・異なる GUID で既存規則を消さない。 |
| 切り替え・複数窓 | 異なるワークスペースのウィンドウが同時に正しい範囲を表示する。A→B→A の途中の遅延結果や、削除前の候補が後から再表示・実行されない。 |
| プレビュー | 個人へスワイプしてキャンセルしても、個人のブックマークや検索結果が途中表示されない。 |
| 無効化・破損 | 明示的な無効化では全件表示になることを示して規則を保持する。読み込み中・規則破損時には自動で全件表示へ戻らず、全件管理から復旧できる。 |
| 性能 | 小規模と1万件程度のブックマークを持つ同じプロファイルで、切り替え・検索の処理時間と主スレッド停止を変更前後で比較する。毎入力での同期的な全件走査を避け、受け入れ可能な予算を検証実装の測定結果から設定する。 |

ネイティブ入力の対応表には、OS バージョン、機器・ドライバー、Linux のセッション方式とデスクトップ環境、必要な OS 設定を記録する。合成イベントでの成功だけを実機対応の根拠にしない。

## 13. 実装の順序と公開条件

| 段階 | 内容 | 公開条件 |
| --- | --- | --- |
| A: ログイン環境と共通操作 | 作成・共有・表示、タブ生成・移動・復元、ボタン、割り当て可能なキー。 | 既存データと複数ウィンドウを含むセッション規則が成立する。既存 API は互換維持。 |
| B: ブックマーク表示範囲 | フォルダー規則、全表示経路、保存・削除、設定バックアップ。 | URL バー等を含む適用範囲と、削除・復元・失敗時の整合性が成立する。ツールバーだけを絞った状態を機能全体の完成とは扱わない。 |
| C: サイドバー入力 | 共通の切り替え要求、プレビュー／キャンセル、水平入力。 | オプトインで、縦横スクロール・Web パネル・ドラッグとの競合を実機確認する。 |
| D: ネイティブ3本指 | OS 別の直接入力アダプター。 | 識別可能な入力と OS 操作との両立を確認した環境のみ試験公開する。ネイティブ変更に必要な成果物も用意する。 |

中核の提供候補は A と B とするが、別々に実装・検証できるようにする。B が未完成の場合、A の提供を止める必要はない。ただしブックマークを含む分離が完成したとは案内しない。C・D の可否で A・B を止めない。

A と並行して、B の URL バー・保存／削除・Sync／GUID・ネイティブメニューの小さな検証実装と、D の各 OS の入力取得を調べる。既存の共通切り替え経路を使い、汎用ジェスチャー基盤の新設や完全プロファイル分離を必須作業に広げない。

### 実装時に確認した点と残る検証

- URL バーの SQL・補完・キーワードへ可視GUIDの制約を適用し、実際のネイティブproviderと小規模／1万件のPlacesで検証した。履歴スコアは保持する。
- 星の選択GUIDだけの編集削除、実フォルダーのCopy・Move・Undo・Redo、GUID変更の規則更新、コピー中断後の保留と復旧を確認した。設定ストアとPlacesをまたぐコピーは、ネイティブ操作の前に保留マーカーを永続化する。
- 標準の明示指定と未指定を区別し、起点の実セッションを優先する生成前の接続点を実装した。既存の属性後書きで実体とずれたタブは、native BrowsingContextのIDを優先する。
- GTKの指本数を取得するソース経路と、プリビルドへJavaScriptを適用する経路を分けた。ネイティブ全体ビルド、実機入力、OS予約との競合、Windows／macOSでの実行は未検証。該当入力を検証済みとして提供しない。

### 初期版で採用しない案

| 案 | 採用しない理由 |
| --- | --- |
| 作成するたびに新しいセッションを自動生成 | 同じ仕事用ログインで案件を増やす需要に合わず、不要な再ログインが増える。分離は明示して選ぶ。 |
| ブックマークをセッションに自動連動 | 同じセッションで表示を分ける使い方と、別セッションへ共通資料を表示する使い方を満たせない。 |
| ワークスペースごとに Places／パスワード DB を持つ | 同期・管理・既存 API への影響が広がり、同一ウィンドウ内の切り替えの改修規模を超える。 |
| ツールバーを CSS で隠すだけ | 検索・星・削除・一括で開く経路が揃わない。 |
| 全 OS の3本指対応を中核の公開条件にする | 入力と OS 予約を未検証のまま約束することになる。共通操作を提供しつつ並行検証する。 |

### 実装と検証の範囲（2026-10-23）

実装は Floorp 側のソースと、固定 Runtime に適用する source/artifact の対応パッチで保持する。

- 段階 A: 作成・共有・既定変更、生成前の実セッション決定、外部要求の受け付け時の固定、新規ウィンドウ、保存済みセッションの復元、欠損時の保留と全通常ウィンドウでの明示復旧、移動時の選択、他ウィンドウで利用中の削除・アーカイブ拒否を実装した。タブの例外・復元保留と分割ペインのセッションを表示する。
- 段階 B: GUID ベースのフォルダー表示範囲、親子の積集合、全ウィンドウでの世代管理、Places の表示・URL バー・パレット・星の編集削除・保存先・フォルダーの移動コピーに同じ可視性を適用する。管理画面とローカル設定のバックアップ・復元、対応付け後の変更確認、競合検査と最後の有効な設定からの復旧を実装した。
- 段階 C: サイドバー内の水平入力を初期オフで追加した。プレビュー、端停止、取消、慣性の抑止、操作対象と開始場所の検査、読み上げ、動きを減らす設定を実装した。既存の循環アクションを維持し、端で止まる次／前のアクションも設定画面から割り当てられる。
- 段階 D: GTK の実際の指本数を取得する専用 ChromeOnly イベントと状態機械、DOM bindings の能力判定、ソースから再ビルドする専用 CI、検証 CLI を用意した。プリビルドへの JavaScript パッチだけではネイティブ入力を提供できないため、通常のパッケージ処理ではネイティブパッチを適用せず、実装のない能力を表示しない。詳細は [ネイティブ入力の対応表と検証手順](workspace-native-input.md) を参照。

通常コンテナを扱う作成・編集画面から Floorp のプライベートコンテナを除外し、既存の実タブのプライベートコンテナは有効な起点として保持する。保存済みパスワード、履歴、拡張機能は共通のままであり、ブックマークの表示先設定をプロファイル分離として説明しない。

## レビュー反映履歴

v0.3 はブックマーク表示範囲の要望と需要調査を受け、セッション／製品の使い方、Places／検索／保存操作、入力と提供範囲の3観点で再検討した。改訂後にも独立レビューを行い、タグ／キーワードの共有、保存中の切り替え、新規ウィンドウ、外部要求の完了、履歴スコア、入力経路の重複に関する指摘を修正し、再確認した。

| 再検討した点 | 改訂内容 |
| --- | --- |
| 新規ワークスペース＝新規セッションという既定 | 現在のワークスペースの既定を共有する初期選択に変更し、別アカウント用の新規環境は明示操作にした。 |
| ブックマークは全件共通という対象範囲 | 保存は共通のまま、フォルダーを選択した複数ワークスペースだけに表示できるようにした。セッションには自動連動させない。 |
| 表示だけの変更では整合しない箇所 | 検索・URL バー・星・編集削除・一括操作・世代管理まで同じ可視性を使う要件を追加した。 |
| 保存済みパスワードと完全分離への期待 | 共有のままであることを説明し、ブックマーク表示やサイトのログイン分離と区別した。 |
| 全 OS とジェスチャーの実現性 | 中核、サイドバー、ネイティブ試験を分け、キー変換で識別できない物理操作の保証を限定した。 |
| 移行・欠損・復元 | 既存データの維持、表示先なしの回復、アーカイブ ID 対応、ローカル設定バックアップを定義した。 |

v0.2 では、セッション規則・既存機能との互換性・ジェスチャーの3観点で独立レビューを実施し、次の P2 指摘を仕様に反映した。

| 指摘 | 反映内容 |
| --- | --- |
| 欠損セッション復旧の適用範囲が未定義 | ワークスペース単位で、同じ旧 ID の既定と保留タブを一貫して復旧する。対象外の定義・アーカイブは変更しない。 |
| 他ウィンドウにタブがある場合の削除・アーカイブが未定義 | 初期版は他ウィンドウで利用中の操作を中止し、共有定義とタブを保つ。 |
| ワークスペース無効時のセッション規則が未定義 | 無効中は独立した新規操作に標準を使い、明示指定・起点・既存タブを維持する。 |
| OS のキー変換ではジェスチャーが端で止まらない | 既存の循環アクションとは別に、端で停止するアクションを追加する。 |
