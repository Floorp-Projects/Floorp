# Recovery27: bounded native group inventory diagnostic

Recovery26 (run 39148209748, producer 117736307902) stopped during checkpoint-rust after three /bin/ps inventory timeouts of 3.320, 3.163 and 3.247 seconds. All 244 actual Mac tests passed. No Rust natural-success boundary, convergence wait, checkpoint upload or consumer build was reached. This remains a monitor-inconclusive result and does not establish a product failure.

The normal Darwin group inventory now runs a dedicated Python helper under the existing 3-second subprocess timeout and three-sample retry budget. It uses read-only KERN_PROC_PID to bind the header-derived kinfo_proc layout to its own libproc PID/birth/EUID/RUID, then KERN_PROC_PGRP for complete group records, including valid zombies and other owners. All byte lengths, record identities and states are checked. ENOMEM partial data is discarded before a fresh bounded query; denied or malformed results remain unknown. Resource counters and existing ownership/generation checks still use libproc. The parent kills and reaps the exact helper after timeout. The private protocol never publishes raw PIDs, credentials or arbitrary exception text.

Only census-abi-compile and census-abi explicitly use bootstrap ps inventory before the ABI file exists. A missing/invalid ABI in a normal stage does not fall back. The binding also records the inventory helper source SHA256. This changes no task resource limits, cleanup signal ownership, strict checkpoint eligibility, convergence rules, SDK permissions or retention.

One short macos-15-intel job runs 267 actual Mac tests with zero skips, then a 60-second experiment with three touched-memory CPU workers (1536 MiB each) and batches of four short child processes. It records complete/unknown/retried sample counts, timeouts, elapsed sample maximum, measured CPU/RSS and backend, and requires exact worker/churn reaps plus a verified-gone monitored group. Known-child and background census observations follow. No SDK acquisition, Floorp build or artifact upload is included. The job remains capped at 20 minutes with an internal 15-minute phase deadline.

This tests whether the replacement inventory works under a short bounded load and preserves zombie, error and cleanup behavior. Passing this experiment does not prove stability throughout a full build or establish the original native host exit cause. A long trial requires a separate decision based on this job's immutable results and the SDK's valid acquisition path.

Primary API source: https://github.com/apple-oss-distributions/xnu/blob/xnu-11417.101.15/bsd/kern/kern_sysctl.c#L787 and #L838; selectors: https://github.com/apple-oss-distributions/xnu/blob/xnu-11417.101.15/bsd/sys/sysctl.h#L947. sysctl_prochandle accounts for every matching live/zombie record and returns ENOMEM when copied capacity is insufficient. proc_listpids was not selected because its independent internal nprocs-plus-slop cap does not establish full caller-visible coverage under process growth.
