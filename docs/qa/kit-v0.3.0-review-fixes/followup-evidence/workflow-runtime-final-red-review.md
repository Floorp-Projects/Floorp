## P2: `_supervise` accepts malformed private result/error envelopes

Location: `.github/workflows/scripts/qa3_native_io.py`, `_supervise`, parent JSON/error/result processing after the bounded read. JSON parser validates UTF-8, duplicate keys, nonfinite numbers and top-level object; budgetUsed is validated as a genuine integer between previous usage and maximum. The parent does not require exact envelope keys, uses truthiness of `reply['error']` rather than error-is-None, and returns `reply['result']` without a typed success-result/completion check.

Independent small fork fixtures inject only the private producer serialization. Nine malformed variants return normally: error `{}`, false, zero or empty string; an extra envelope key; result null or scalar; a result with ownedCleanupComplete false; a result with exit true. Missing keys, duplicate JSON and bool/null/string/regressed/excessive budget are rejected. A normal OSError error reconstructs its errno. A synthetic SystemExit(0) error reconstructs SystemExit with code 0; natural reachability through current native operations has not been established, so this is not reported as a real successful qualified run.

Recommendation: validate exact envelope keys before interpretation; require error None or a typed error object; validate success-result keys/field types and owned cleanup true in the run_owned-specific layer; preserve allow_nonzero semantics; convert malformed protocol to a failure exception. Preserve the bounded pipe, parent deadlines, original error details and monotonic shared I/O budget. The author is repairing this under root's direction.

Severity and limits: **P2 defensive protocol robustness**, not a proven public/private credential, qualification or publication bypass. The writer normally belongs to the trusted fork child; the target Popen does not inherit it. Generating these malformed values requires a fake private producer in the fixture. Public shadow/Draft guard preservation remains separate from private proof readiness. New native execution remains No-Go for the existing launcher/job-scope/worker prerequisites as well as the outstanding initialization repair.
