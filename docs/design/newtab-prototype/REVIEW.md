## 意図的な調整とコピーの比較

- 正式なロゴ、ブランドアイコン、既存 Hub 部品を使用する。生成画像のロゴの形や部品サイズの揺れは引き継がない。
- 4画面のヘッダーは共通80pxへ揃え、狭幅では112pxの2段構成とする。
- ホームのサイトは、専用画面と同じブックマーク順の先頭6件を使う。参照画像のホームにある Figma／Notion／Wikipedia は、デモの開発グループの並び順に従って Deno／React／TypeScript になっている。
- 生成画像中の版番号付き記事タイトルなどは、実際のリリースと誤認されない自作のサンプル記事へ置き換える。ナビ、見出し、追加操作、スポンサー表記、リーダーへの入口は維持する。
- Hub の背景は、プロトタイプで確認できるラベンダー／ホワイトを用意する。暗色や画像の選択部品を、未対応のまま置かない。
- 初期の6列、15分の更新間隔、記事を開いたときの既読化は、デザイン確認用の仮値として明示する。

上記の調整以外に、意図せず追加・欠落した主要ナビや、先頭画面の説明用ラベルはない。
参照案の構造・配色・部品の扱いに沿って表示を確認した。画像とのピクセル単位の一致ではなく、既存 Floorp の正規資産と合意済み仕様を優先している。

## 操作確認

独立した新規ブラウザーコンテキストで9シナリオ、40超の操作・状態確認を実行した。

- ワークスペース変更と RSS の既読・スター状態の共有。
- ホーム記事→リーダー、全文配信／抜粋の本文、記事 URL のリンク。
- スポンサー2枠、個別非表示、一括切り替え、復元、サイトとして保存、再読み込み後の保持。
- Hub の割り当て変更、一時的なグループ切り替えとの区別。
- サイトの追加・編集・削除・メニューによる並べ替え。
- 購読先の追加、記事ゼロ、購読未設定の空状態。
- 狭幅の一覧↔本文、一覧位置の保持、購読先の収納。

390・700・960px × 4画面の12組で水平のはみ出しなし。
親側でも 320・390・700・960px のホーム・リーダー・Hub を確認した。
実行時の `pageerror` は0件。

修正して再確認した問題:

1. 記事の外部リンクが配信元のトップページを参照していた点を、各記事の URL 参照へ修正。
2. タッチ環境で購読解除ボタンのクリックが下の項目に渡る点を、ボタンのポインター操作を有効にして修正。

型検査と Vite ビルドは成功した。単体 HTML を `file://` から開き、5画面の表示、グループの矢印キー操作、ダイアログの Escape とフォーカス復帰、Hub のスポンサー切り替えと再読み込み後の保持を確認した。
単体 HTML での表示時は、HTTP/HTTPS のネットワーク要求0件、`pageerror` 0件。
実製品の Firefox Actor・ブックマーク・設定移行・RSS 通信の検証は、このプロトタイプの確認に含まれない。
