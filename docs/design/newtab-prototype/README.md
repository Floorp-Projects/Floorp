# 新しいタブの操作プロトタイプ

ホーム、スピードダイアル、RSS リーダー、Floorp Hub の設定ページを確認するための操作プロトタイプ。基本仕様とデザインは 2026-10-29 に了承済みで、入れ子フォルダーを含む最新版を本体実装の基準とする。
製品コードへの組み込み前の段階であり、[合意済みの製品仕様](../../newtab-speed-dial-rss-spec.md)を元に画面と操作を具体化している。

見た目は、現行 Floorp Hub と [Web-v5 のデザインシステム](https://github.com/Floorp-Projects/web-v5/blob/master/docs/design-system/README.md)を基準とする。文字・操作部品は Hub に揃え、新しいタブでは既存の背景機能を引き継ぐ。背景画像の上に置く白い面は、サイト名や記事を読みやすくするためのもの。「背景を透かす」を有効にすると、半透明の面と控えめなぼかしで壁紙の色を取り込む。採用基準と参照資料は [DESIGN.md](DESIGN.md) を参照。

本体実装の文書は[仕様書・設計書・実装計画書の一覧](../../newtab-speed-dial-rss/README.md)を参照。ここは画面確認用プロトタイプの説明であり、本体の保存方式・APIの正本ではない。

## 開く

- 単体ファイル: ビルド後の `dist/preview.html` をブラウザーで開く。必要なスクリプト、CSS、書体、ロゴを含むので、プレビュー用サーバーは不要。
- 開発用: リポジトリの依存関係が導入済みの状態で、このディレクトリーから `npm run dev`。入口は `http://localhost:5187/`。
- 型検査: `npm run check`。
- ビルドと単体ファイル作成: `npm run build`。

画面の入口は `#home`、`#dial`、`#feed`、`#hub/general`、`#hub/dial`、`#hub/feed`、`#hub/sponsors`。
単体ファイルの URL にも同じハッシュを付けられる。

## 試せること

1. 上部のワークスペースを切り替え、Speed Dial のグループだけが変わることを確認する。
2. サイトやフォルダーを追加する。フォルダータイルを開き、その中にさらにフォルダーを作る。パンくずと「一つ上へ」で上の階層へ戻る。
3. サイトの保存先を選ぶ、フォルダーの名前を変える、サイトやフォルダーを移動する操作を確認する。自分自身や子孫の中への循環移動は受け付けない。フォルダーを削除するときは内包する項目数と確認表示を確認する。
4. 並び順はタイルのドラッグ、またはメニューの「前へ移動／後ろへ移動」で変更する。
5. ホームの記事からフィードへ移動し、既読・スター・検索・購読先を操作する。
6. スポンサーのメニューから個別に非表示にする、または自分の Speed Dial に保存する。
7. 設定ボタンから Hub へ移動し、表示項目・配置・グループ割り当て・スポンサー表示を変更する。ホームへ戻って反映を確認する。
8. Hub の「背景」で背景なし・ランダム・自分の画像・フォルダー内の画像・Floorp の画像を切り替える。ランダム／フォルダーではスライドショーと秒数を変更する。
9. ホームで現在時刻・地域化された日付を確認する。時計の表示・非表示は Hub から変更する。
10. ページを再読み込みして、デモ設定、サイトとフォルダーの階層、選択した画像、記事状態が保持されることを確認する。

デモ状態と自分の背景画像は `localStorage` の `floorp-newtab-design-v1` に保存する。フォルダーから選んだ画像は IndexedDB の `floorp-newtab-design-media` に保存する。状態を初期化するには前者のキーを削除し、取り込んだフォルダー画像も消す場合は後者のデータベースを削除して再読み込みする。

## 背景と既存機能の扱い

- 背景の5方式と、ランダム／フォルダー向けのスライドショーを引き継ぐ。新規デモの既定は現行と同じランダム、スライドショー無効、間隔30秒。方式を切り替えても、以前に選んだ自分の画像やフォルダーを保持する。
- 単体プレビューの容量を抑えるため、ランダム背景は現行の内蔵画像100枚から3枚を見本として収録する。製品では100枚を維持する。Floorp の背景画像は既存の6枚を収録する。
- プロトタイプのフォルダー選択は、一般のブラウザーで画像を取り込み、フォルダー名を表示する動作。製品では既存のネイティブ選択画面・フォルダーパス・保存値を引き継ぎ、フォルダー内の画像を参照する。
- 時計は固定サンプルの日付から、現在時刻とブラウザーの地域設定に沿った日付へ変更した。
- 現行機能全体の継承方針は[製品仕様](../../newtab-speed-dial-rss-spec.md)に記載する。このプロトタイプは、既存設定の移行や既存機能すべての接続を完了したものではない。

Hub の背景設定にある「背景を透かす」で、不透明な表示へ戻せる。OS の透明効果軽減・強制カラーにも対応する。ぼかし非対応では不透明表示になる。

## デザイン上の提案

- 検索バーは画面の左右中央に配置する。「開発のホーム」などの見出しと説明文は表示せず、時計は右上に残す。
- ホームは現在のグループ直下の先頭6項目（サイトとフォルダー）を表示し、スポンサー2枠を追加する。「すべて見る」で Speed Dial 全体へ、フォルダータイルで該当フォルダーへ移動する。
- グループを入口として、フォルダーを任意の深さへ入れ子にできる。現在位置はパンくずで示し、ワークスペース・グループ切り替えでは入口へ戻る。フォルダーの作成・名前変更・移動・削除、保存先選択などの細部は、今回の操作案として確認する。
- スポンサーはブックマーク階層と別管理し、フォルダー内にも同じ2枠を共通表示する。RSS の状態も共通のままとする。
- デスクトップの専用 Speed Dial は初期6列、ホームは4列を基本として幅に合わせて減らす。列数・既読判定・更新間隔は、最終仕様ではなくプロトタイプで確認する案。
- フィード画面を専用リーダーにし、広い画面は購読先・一覧・本文の3領域、狭い画面は一覧と本文を切り替える。
- 新しいタブの設定パネルは設けず、Hub の独立ページへ移動する。
- サイトのスクリーンショットではなく、アイコンと名前を中心にしたタイルで比較・検索しやすさを確認する。

## 実データとの関係

プロトタイプはブラウザーの実ブックマーク、Floorp の設定値、RSS のネットワーク取得、広告配信サービスへ接続していない。
記事、購読先、スポンサー名、記事 URL はデザイン用サンプルであり、外部ページの実在や広告掲載の契約を示すものではない。
「元サイトで開く」は各サンプル記事の URL を使用する。製品実装では RSS 項目の実際のリンクを使う。
ウェブ検索のサンプル動作は DuckDuckGo を使う。製品では現行と同じく検索欄からブラウザーの URL バーへフォーカスし、URL バー経由で検索・移動する。

フォルダー階層とサイトの操作はデモデータに保存する。製品の Places との連動、設定移行、RSS の取得・保存は、デザイン確認後の実装・検証対象。製品では Speed Dial 独自の固定の階層数制限を設けず、通常のブックマークフォルダーの構造を引き継ぐ。
元サイトから本文を追加で抽出する機能は、継続方針として設けない。

## 使用している既存資産

React、Vite、lucide-react、Simple Icons と、Floorp のロゴ・ローカルフォント・共通 UI・既存の背景画像を使用する。
Hub の入力欄・ボタン・スイッチは `libs/ui` の既存部品を再利用し、Chakra の標準トークンを適用している。

`dist/` は生成物として Git の対象から除外する。
