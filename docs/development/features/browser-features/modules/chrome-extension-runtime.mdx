# Chrome Extension Compatibility Runtime

This integration implements part of the Chrome Extension Runtime v2 plan. It
does not establish a compatibility rate or release readiness. The reference
Runtime is the source commit in `floorp-runtime.lock.json`:
`1553b7b550dfe555684628d175e0c1701a785d0b`, Firefox 157.0,
build `20260926171135`. The earlier plan's `7dd6197` baseline is superseded.

## Package authentication and identity

`CRXConverterClass.convert()` authenticates a snapshot of the CRX before exposing
its ZIP contents to conversion. CRX2 uses its RSA/SHA-1 proof; CRX3 verifies its
signed header and RSA/SHA-256 or P-256 ECDSA/SHA-256 proofs. The developer public
key must derive the requested Chrome extension ID. A signed header that merely
declares another extension's ID is insufficient. Modified payloads, malformed
proofs, and a mismatched requested ID are rejected.

Initial installation and manual updates share `downloadChromeExtension()`. It
omits profile credentials, tries only the two configured download endpoints, and
enforces a 100 MiB limit using both declared length and streamed bytes, with a
five-minute timeout per endpoint. Failed or oversized streams are cancelled.
After signature verification, ZIP conversion limits expanded entries to 50 MiB
each, 500 MiB in total, and 10,000 entries. These bounds are separate from package
authentication.

Both download attempts use the actual browser process OS and architecture and
the fixed package-selection reference `155.0.8059.84`. They never switch to a
Windows package on another OS. Unsupported targets fail explicitly. Conversion
validates `minimum_chrome_version` against that reference, preserves accepted
values, and rejects newer requirements without comparing them to Gecko's version.
This bound does not establish support for every API in Chrome 155.

Converted extensions retain their internal Gecko ID,
`<chrome-id>@chromium-extension`, preserving permission and storage keys. Their
manifest contains:

```json
{
  "browser_specific_settings": {
    "gecko": {
      "floorp_chrome_extension": {
        "schema_version": 1,
        "original_id": "abcdefghijklmnopabcdefghijklmnop"
      }
    }
  }
}
```

The Runtime validates the schema version, the 32-character `a`–`p` alphabet,
and the matching installed ID before selecting compatibility behavior. Compatible
contexts see the original Chrome `runtime.id`; native routing, permissions,
storage, and `runtime.getURL()` continue to use Gecko's working identities and
`moz-extension://` URLs. Ordinary Firefox extensions retain their public IDs,
APIs, and native-host protocol.

The marker is a compatibility selector, not authenticated installed-XPI
provenance. CRX verification authenticates the input to the converter; a marker
or conversion report inside an installed XPI cannot independently prove that it
passed through the converter or came from a store. This distinction also applies
to diagnostics shown in the management UI.

The package stores the original manifest bytes at
`__floorp_chrome__/original-manifest.json` and a versioned report at
`__floorp_chrome__/conversion-report.json`. The report includes both IDs, the
original version, warnings, removed permissions, and recorded CRX signature
format, algorithm, and public-key SHA-256. A source package using this reserved
directory is rejected. `convert()` returns the report as well.

Existing installations need explicit reconversion to receive new conversion
metadata or transformed resources. The manual update flow below supports this;
automatic migration and automatic update scheduling are not implemented.

## Implemented behavior and limits

| Area | Behavior | Current limits |
| --- | --- | --- |
| MV3 background | Preserve default classic, explicit classic, and module script types; prefer an existing cross-browser document background; report the event-page fallback. | The distributed Runtime has `MOZ_WEBEXT_WEBIDL_ENABLED=false`. Native extension Service Workers and their missing Worker APIs require a rebuilt Runtime and further implementation. See the [Worker assessment](./chrome-extension-service-workers.mdx). |
| Documents | Use native Gecko document UUIDs in navigation, scripting, messages, and contexts. Remove injected synthetic IDs and frame-ID rewriting. | The minimum converter target defaults to Gecko 157. No synthetic fallback is provided for older engines. |
| Offscreen | Extension-owned hidden document independent of the event page; singleton reservation, own-origin validation, cancellation and shutdown cleanup; native `OFFSCREEN_DOCUMENT` contexts; runtime-only extension APIs; audio silence lifetime. | Native Worker callers remain unavailable. Audio-silence lifecycle tests do not establish device-audio capture support. |
| Tab capture | Video-only `tabCapture.capture`, `getMediaStreamId`, `getCapturedTabs`, and `onStatusChanged`; single-use, expiring stream IDs consumable by the same extension, including Offscreen. Actual action invocation grants access to the selected document. | Tab audio, desktop capture tokens, and `consumerTabId` are unsupported and reject explicitly. No release qualification is claimed. |
| Side Panel | Native `sidePanel` namespace rendered by the browser sidebar, global/tab options, explicit window targeting, open/close, action toggling, and disabled-tab hide/restore. Equal URLs in different configured scopes receive fresh documents; unconfigured tabs inherit the global instance. | Scope switches recreate documents. Inactive-tab opening/closing, full Chrome events, independently retained panel documents, and Floorp pinning/workspace controls require more work. |
| Native Messaging | Compatible extensions can discover Chrome/Chromium hosts, require exact `allowed_origins`, and launch with the original Chrome origin. Mozilla hosts retain priority and Firefox launch arguments. | Linux executable exchange is tested. Windows/macOS lookup and launch branches need platform execution. Sandboxed portal discovery retains existing Mozilla behavior. |
| Extension messaging | Expose original public Chrome IDs and translate exact installed compatible targets for messages and Ports. Enforce `externally_connectable.ids` before waking a compatible target. Keep internal same-extension/external classification and Firefox sender identity behavior. | Web-page API injection and `externally_connectable.matches` authorization are unimplemented. A Gecko-ID suffix alone does not authenticate a Chrome-ID caller. |
| Proxy | Translate Chrome `proxy.settings` values for `direct`, `auto_detect`, `system`, `fixed_servers`, and `pac_script`; support callbacks/Promises, native ownership, clear/restore, and persistent `onChange` events. Fixed rules and inline/URL PAC use Gecko's real network backend. | Only regular scope is supported. Incognito-specific queries/scopes, mandatory PAC, QUIC proxies, and unsupported bypass patterns such as CIDR reject. Modifying settings retains Gecko's requirement that the extension be allowed in private windows. |
| Static DNR conversion | Preserve constraints; map deprecated `domains`/`excludedDomains` to initiator fields with diagnostics; reject invalid or unknown matching constraints. | Full action/regex validation and runtime limits remain Gecko's responsibility. Dynamic/session differential compatibility has not been established. |
| Management | Add diagnostics to existing `about:addons` details: recorded source ID/version, schema, conversion warnings, removed permissions, and actual running contexts; refresh, active-extension reload, JSON export, and explicit update/reconversion controls. English/Japanese strings are provided. | Diagnostics do not attest package provenance or certify compatibility. Legacy packages are labeled unverified; ordinary Firefox extensions keep the section hidden. |
| Updates | Download, authenticate, and convert a candidate, then apply it through the normal Add-on Manager permission flow after a separate explicit action. Support explicit same-version reconversion without downgrading. | Manual only. Automatic scheduling and an authenticated installed-package migration policy are not provided by this service. |

Tab capture distinguishes actual action invocation from hover/preload or a generic
`activeTab` grant. Its tokens expire after ten seconds and bind to the issuing
extension and target document. Consumed video belongs to the consumer document,
so an Offscreen consumer can outlive background suspension. Target-document
replacement, source-tab closure, and consumer shutdown revoke capture; native
tests verify that actual stream tracks end. Ordinary camera access still requires
the native permission prompt, even while a capture backend permit is pending.
This does not grant unrestricted screen capture or remove the browser's ordinary
user-interaction checks.

Audio needs a separate native implementation: the pinned
`dom/media/MediaManager.cpp` audio-capture source binds to the requesting window,
and the existing WebDriver capture path explicitly rejects audio (bug 2047554).
The video bridge cannot supply arbitrary target-tab audio through a JavaScript
alias. Desktop selection and token handling also remain unimplemented.

Proxy endpoints support HTTP, HTTPS, SOCKS4, and SOCKS5. Fixed-server rules use
generated PAC, including single/per-protocol/fallback rules and supported hostname
bypass patterns. PAC scripts run through Gecko's PAC backend rather than in the
privileged API process. Invalid settings are rejected before changing the active
configuration. Broader Chrome/Gecko network behavior still needs differential
testing.

## Manual updates and diagnostics

The production service is
`resource://noraneko/modules/chrome-web-store/ChromeExtensionUpdater.sys.mjs`,
exporting `ChromeExtensionUpdater`. `checkForUpdate(addonId)` only prepares an
authenticated candidate and returns its version and warnings. Calling it with
`{reconvert: true}` can prepare the same version for explicit conversion
migration. `installUpdate(addonId, browser)` consumes that candidate and uses the
actual Add-on Manager browser embedder for normal permission confirmation.

The `about:addons` Check and Reapply controls prepare candidates; Apply is a
separate action. Candidates expire after ten minutes. The service rejects
superseded checks and rechecks the exact existing version and prepared candidate
before entering the native permission flow. A postponed native update is reported
as postponed and retains its source package until it completes or is cancelled.
Tests exercise normal persistent updates and same-version reconversion, including stable
identity, retained storage and grants, permission rejection, competing installs,
and postponed installation.

An old package with an exact Chrome-shaped internal ID and matching manifest ID
can be selected for manual migration without already having the marker. Its
downloaded replacement must still pass CRX signature and developer-ID checks
before receiving current conversion metadata. Displaying its legacy diagnostics
does not grant compatibility APIs.

The diagnostics collector reads packaged resources and live native contexts
without waking a stopped background. Reload is disabled for inactive extensions
so it cannot accidentally enable one. Export writes a JSON snapshot after a save
destination is chosen; it copies only recognized signature fields with valid
shapes and does not export arbitrary report properties. Those fields remain
recorded converter metadata, not independent proof about the installed XPI.

## Runtime patches and verification

Seven common source patches implement the native integration, each with a
matching `tools/patches` patch for the unpacked development artifact:

- `chrome-extension-native-messaging.patch`: shared metadata schema and native-host protocol selection.
- `chrome-extension-offscreen.patch`: hidden document host, contexts, and compatible child API gating.
- `chrome-side-panel.patch`: native sidebar and action integration.
- `chrome-extension-messaging.patch`: public Chrome IDs and extension-target routing/authorization.
- `chrome-extension-proxy.patch`: Chrome settings translation through Gecko's network backend.
- `chrome-extension-diagnostics.patch`: existing Add-on Manager details integration.
- `chrome-extension-capture.patch`: document-bound video capture and stream lifecycle.

The lock continues to reference the exact prebuilt Runtime. Changing a lock hash
or applying a C++/WebIDL patch during artifact packaging would not compile new
native bindings.

Initialize the existing cloud environment when applicable:

```sh
source /workspace/.floorp-cloud/env.sh
```

Check that all source patches compose against the locked commit and have matching
development paths, valid JSON, and parseable JavaScript:

```sh
python3 tools/chrome-extension-runtime/check-patches.py
```

The check reconstructs affected source files in a temporary Git fixture without
editing the Runtime checkout. Development API tests require the corresponding
artifact patches to be applied. Run `git apply` from the Floorp root with
`--directory=_dist/bin/floorp`; invoking it within the nested artifact can skip
files while exiting successfully. Confirm the expected files exist and that the
reverse patch is applicable before interpreting API test results.

Run browser suites without rebuilding or re-extracting the artifact:

```sh
python3 tools/chrome-extension-runtime/run-browser-tests.py \
  --browser _dist/bin/floorp/floorp \
  --test browser-features/modules/modules/chrome-web-store/test/polyfills/documentId/DocumentIdPolyfill.test.mts \
  --test browser-features/modules/modules/chrome-web-store/test/polyfills/offscreen/OffscreenNative.test.mts \
  --test browser-features/modules/modules/chrome-web-store/test/ChromeMessagingNative.test.mts \
  --test browser-features/modules/modules/chrome-web-store/test/CRXVerifier.test.mts \
  --test browser-features/modules/modules/chrome-web-store/test/ChromeExtensionDownload.test.mts \
  --test browser-features/modules/modules/chrome-web-store/test/ChromeExtensionUpdater.test.mts
python3 tools/chrome-extension-runtime/test-native-messaging.py \
  --binary _dist/bin/floorp/floorp
python3 tools/chrome-extension-runtime/test-side-panel.py \
  --browser _dist/bin/floorp/floorp
python3 tools/chrome-extension-runtime/test-proxy.py \
  --browser _dist/bin/floorp/floorp
python3 tools/chrome-extension-runtime/test-diagnostics-ui.py \
  --browser _dist/bin/floorp/floorp
python3 tools/chrome-extension-runtime/run-browser-tests.py \
  --browser _dist/bin/floorp/floorp \
  --test tools/chrome-extension-runtime/updater-import-smoke.mts
```

Each run uses a private profile, writes a fresh JSON report, and terminates its own
browser. Native Messaging separately reconstructs its locked source fixture and
tests an executable host and framed JSON. Updater fixtures use signed CRX inputs
and real Add-on Manager installations with a signing preference scoped to their
test profile. The production import smoke runs without the UI updater fixture.
The UI suite substitutes only its update service in its private process to test
controls and embedder wiring; it does not replace the production updater tests.

Linux verification includes composed source/development patches, converter and
signature suites, native document navigation, Offscreen lifecycle/messages/Ports,
executable Chrome/Firefox host exchanges, extension-to-extension messages and
Ports, real proxy traffic, and manual update/reconversion fixtures. The Side Panel
runner passes 17 checks, and actual `about:addons` interactions pass 28 checks,
including English/Japanese rendering and real export/reload operations. Native
capture tests verify real video pixels and WebM output, action versus
preload authorization, single-use tokens, and track termination on navigation,
source-tab closure, or Offscreen destruction. A separate fake-camera test verifies
the real permission prompt and denial; it is not used as the video success proof.
The Side Panel
[implementation notes](../../../../investigations/chrome-side-panel-runtime.md)
describe its remaining lifetime differences.

Six shared-downloader tests cover invalid IDs, credential omission and byte
ordering, declared and streamed size limits, response cleanup/fallback, and
propagated network failures. The final combined browser run passes 20 suites;
33 host tests pass. Verification reports are collected in
`_dist/chrome-runtime-tests/verification-summary.json`, including the exact
Runtime baseline and the unfulfilled release criteria. These are development
checks, not a measured extension compatibility percentage.

## Chrome reference comparison

The Linux reference is frozen to official Google Chrome `155.0.8059.84`
(`google-chrome-stable` package `155.0.8059.84-1`, amd64). Its package checksum
was checked through Google's signed repository metadata, and the executable
version and checksum were recorded:

| Artifact | SHA-256 |
| --- | --- |
| Chrome Debian package | `8fbd2ae69cdf7ee98b7513c3396a7b5e06f974f8625fdd590df3091dd0c3e9de` |
| Chrome executable | `cb19b59995072b86cc7f887b3b1c7ab1f63518a7f2ed9f0d33249e1a040e2c76` |
| Self-authored comparison fixture | `2b2d6a495ae7385560b2e3f328f715ade6fc00f6e27a0b339624010195343008` |

Run the fixture against both browsers using private profiles:

```sh
node tools/chrome-extension-runtime/compare-reference.mjs \
  --chrome _dist/chrome-reference/extracted/opt/google/chrome/chrome \
  --floorp _dist/bin/floorp/floorp
```

The runner checks the frozen Chrome version and executable checksum, then writes
both raw observations and normalized comparison results under
`_dist/chrome-runtime-tests/comparison-*/report.json`. The completed comparison
in `comparison-87vrfo/report.json` passes for one self-authored fixture: original
public identity, self messages and Ports, `runtime.getURL()` resource fetching,
native contexts and ID filters, and Offscreen creation, messaging, close, and
replacement document identity.

The report explicitly retains expected differences: Chrome executes a native MV3
Service Worker, while this Floorp artifact executes a DOM event-page fallback;
extension URLs use each browser's real scheme. Matching the selected normalized
observations does not establish Worker equivalence or real-world extension
compatibility. This fixture is not the planned 50-extension corpus.

## Remaining release work

The release remains a single integrated target. It still needs native classic and
module Worker execution and stop/restart event delivery, audio and desktop
capture support, full Side Panel semantics, debugger/CDP
translation, web-page external messaging and identity, Chrome extension URL
resolution, further API and proxy differences, and automatic updates. Unsupported APIs must not be advertised
through successful empty stubs.

The Chrome reference build is frozen, but the 50-extension corpus, its exact
versions, and primary operations remain unfrozen. No measured compatibility
percentage is available. Release qualification also requires broader
network/side-effect differential tests, real-extension upgrade and
Firefox-extension regressions, and Windows/macOS/Linux packaged builds. Linux
development fixtures do not satisfy those release gates. Windows and macOS
execution environments are not available in this workspace. A native Runtime
candidate with the missing Worker/audio implementation must be built and
qualified before the full plan can be completed.
