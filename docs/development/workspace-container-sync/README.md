# ワークスペース同期のコンテナ対応

作成日: 2026-10-28（日本時間）

同期したワークスペースとタブを、各端末の適切なコンテナで開くための文書一式。
既存のログイン状態を利用し、一致するコンテナがない初回受信では新規作成する。
Cookie・認証状態そのものは同期しない。

## 決定内容

- ワークスペースの既定コンテナと、タブの実際の所属を扱う。
- 関連付け済みなら再利用。同名候補は初回確認・選択、一致なしなら初回に作成する。
- 名前変更後も ID の対応を保持する。
- 関連付け先削除はその端末の問題として扱い、再設定を待つ。
- コンテナ削除によるタブ閉鎖を他端末へ送らない。
- 既存タブを別コンテナへ移す場合は、明示操作で開き直す。

## 実装と検証の状態

合意済みの機能仕様に基づく製品コード・Runtime patch・回帰試験を実装中。 専用 v2
コレクション、native Sync の条件付き書き込みによる移行所有権、
削除前の永続保護を実装した。仕様書の利用者向けの合意は変更していない。

実装ベースは Floorp `c122afebbdbb4627a3d342c5b8d969686024c7e9`、 Runtime は
`0ac255739cdd64e100cd6913329247421b0ec2ea`（Gecko 159）。 完全な Linux Floorp
アプリと隔離プロフィールで、native 暗号化・ページ取得・CAS・
中断再開を含む移行試験と、削除 lifecycle 試験を実施した。
実施済みケースと証拠は[実装計画書の検証記録](implementation-plan.md#61-実施済みの検証記録)に記載する。
最終統合版、実アカウントの二クライアント QA、異 OS の検証は完了していない。

## 移行と復旧の制限

- 新版は `floorp-workspaces-v2` を使用する。旧 `floorp-workspaces`
  は変更・削除しない。 移行完了後の変更は対応版同士だけで同期する。
- 完了マーカーを確認した端末は、旧サーバーデータや、そのプロフィールに残る旧版の遅延編集を
  v2 へ自動再投入しない。旧ローカルファイルは保全するが、明示回収 UI
  は今回未実装。
- 移行中は所有元プロフィールの永続ジャーナルから再開する。他端末は所有権を奪わない。
  所有元のジャーナル紛失時は同期を止める。所有権移管・手動復旧 UI は未実装。
- コンテナ削除・コンテナ機能全体の無効化後は、関連付けを削除済みとして保持する。
  再有効化や同じ数値 ID
  の再利用で自動復旧せず、明示的な再関連付け・新規作成を待つ。

設計上の根拠と移行の確定手順は[設計書](design.md)、
残る検証と公開条件は[実装計画書](implementation-plan.md)を参照する。
