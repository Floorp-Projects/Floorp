# ワークスペース同期のコンテナ対応 — 仕様書

作成日: 2026-10-28（日本時間）

状態: 合意した機能仕様と、実装に向けた補完方針。未実装・未検証。

関連文書: [設計書](design.md) / [実装計画書](implementation-plan.md)

## 1. 目的

同期で受信したワークスペースとタブを、受信側の適切なコンテナで開く。
受信側にログイン済みのコンテナがある場合は、そのログイン状態を利用する。
該当するコンテナがない初回受信では、同期元の情報からコンテナを作成する。

本機能はコンテナの対応付けを提供する。Cookie やログインセッションの移送は行わない。
新規作成したコンテナでは、各サイトへの初回ログインが必要になる。

## 3. 対象と用語

| 用語 | 意味 |
| --- | --- |
| 同期コンテナ | 端末をまたいで参照する論理上のコンテナ。同期用の共通 ID を持つ |
| ローカルコンテナ | 各プロフィール上に存在する実際のコンテナ。端末内の ID を持つ |
| 関連付け | 同期コンテナと、そのプロフィールのローカルコンテナとの対応 |
| ワークスペース既定 | タブを新しく作る際に通常使用するコンテナ |
| タブの所属 | タブが実際に使用しているコンテナ。明示的な「コンテナなし」も含む |
| 初回未関連付け | 対応先がまだ決まっていない状態 |
| 関連付け先削除 | 一度関連付けたローカルコンテナが存在しなくなった状態 |

対象はコンテナ機能を利用できる Floorp Desktop の通常プロフィールとする。
同一プロフィールの全ウィンドウで関連付けを共有する。
モバイルや他ブラウザーでのコンテナ再現は、本機能の初期提供範囲に含めない。
既存同期が対象外とするプライベートウィンドウ・URL・データは、引き続き対象外とする。

## 4. 機能要件

### FR-01: ワークスペースとタブの両方を扱う

ワークスペースの既定コンテナと、タブごとの所属コンテナを同期の対象にする。
タブに明示的な指定がある場合は、その指定を優先する。「コンテナなし」も有効な指定とする。
既定コンテナの変更だけで、既に開いているタブの所属を変更しない。

### FR-02: 共通 ID で対応を記憶する

端末内のコンテナ番号を、そのまま他端末のコンテナ番号として扱わない。
同期用の共通 ID とローカルコンテナの対応を保存し、以後の受信に使用する。
関連付け後にコンテナ名が変わっても、名前で再検索して重複作成しない。
同じ同期コンテナを参照する複数ワークスペース・タブは、同じ関連付けを再利用する。

### FR-03: 既存コンテナを再利用する

有効な関連付けがなく、同名のローカルコンテナがある場合は、それを候補にする。
候補が一件でも、初回に関連付けを確認する。複数ある場合は使用する候補を選択する。
確認・選択が済むまで、そのコンテナを必要とする受信タブを開かない。
関連付けを保存した後は、毎回の確認を求めない。

### FR-04: 初回に一致しなければ作成する

初回未関連付けで同名候補がない場合、同期元の名前・色・アイコンで新規作成する。
コンテナ作成と関連付けの保存を完了してから、受信タブを開く。
同じ情報を繰り返し受信しても、同じコンテナを重複作成しない。
作成に失敗した場合は保留して理由を表示し、通常コンテナへの代替展開は行わない。

### FR-05: 受信タブを正しいコンテナで読み込む

コンテナを決める前に対象サイトへの読み込みを始めない。
別のワークスペースを表示中でも、受信対象のワークスペース・タブの対応先を使用する。
同期元と受信側のコンテナ番号が異なる場合も、正しい関連付け先で開く。

### FR-06: 各端末のログイン状態を利用する

既存コンテナを再利用した場合、そのコンテナにある Cookie とサイトデータを使用する。
関連付け処理によって、既存の Cookie やサイトデータをコピー・上書き・消去しない。
新規作成したコンテナに、同期元のログイン状態が再現されるとは表示しない。

### FR-07: 既存タブの変更を明示操作にする

関連付けや既定コンテナの設定変更によって、作業中のタブを自動で開き直さない。
既存タブへの適用は、対象を確認できる「選択したコンテナで開き直す」操作として提供する。
開き直す前に、対象タブと対応先を示す。フォーム入力やページ内状態の完全な移行は保証しない。
新しく受信するタブには、解決済みの関連付けを適用する。

### FR-08: 関連付け先削除を、その端末の状態として扱う

関連付け済みのローカルコンテナが削除された場合、その関連付けを使用不能にする。
初回未関連付けとは区別し、自動で同名コンテナを作り直さない。
通常コンテナへ切り替えて対象タブを開くこともしない。
他端末のコンテナ・タブ・ログイン状態は維持する。

### FR-09: 削除後に対応先を決め直せる

影響を受けるワークスペースに理由を表示し、対象コンテナで開く必要がある受信タブを保留する。
ユーザーは「既存コンテナへ再関連付け」「新規作成」「そのワークスペースの同期解除」を選べる。
再関連付け・新規作成が完了したら、未生成または削除により消えた保護タブのうち、現在も有効なものを展開する。
削除後も実タブが残る経路では、FR-07 に従って明示的な開き直しを待つ。
同期元で既に閉じられたタブを、保留時の古い一覧から再度開かない。

### FR-10: 削除に伴う閉鎖を他端末へ伝えない

コンテナ削除が原因でタブが閉じた場合、それを通常の同期タブ削除として送信しない。
この区別はブラウザー再起動後も保持し、後の差分取得で削除に変換しない。
ユーザーによる通常のタブ閉鎖や、他端末からの正当な削除は、従来どおり同期する。
原因を区別できない実装を提供してはならず、削除順序の検証をリリース条件にする。

### FR-11: 解除・削除で端末のコンテナを消さない

ワークスペースの同期解除・削除や、関連付けの解除だけでは、ローカルコンテナを削除しない。
他のワークスペースや通常タブで同じコンテナが使われている場合も維持する。
コンテナ自身の削除操作は、ブラウザーのコンテナ管理機能で行う。

### FR-12: 状態と復旧方法を表示する（実装上の補完）

最低限「関連付け待ち」「関連付け先が削除された」「作成失敗」を区別する。
状態表示には該当するコンテナと復旧操作を含める。通信エラーと関連付け待ちを混同しない。
ダイアログを閉じても保留状態を維持し、同じ内容の確認を各ウィンドウで重複表示しない。
必要な操作はキーボードから利用でき、状態と対象名を支援技術でも取得できるようにする。

### FR-13: 同期対象外のデータを維持する

Cookie、認証トークン、localStorage、IndexedDB、閲覧履歴、フォーム内容は同期しない。
コンテナ内のサイトデータ全体の同期や、サイトを特定コンテナへ振り分けるルールの同期は対象外。
既存コンテナ拡張の設定全体を取り込む機能も、この初期範囲には含めない。

### FR-14: 互換性を公開条件とする（実装上の補完）

コンテナ参照を含む新版の変更を、情報を理解できない旧版が受信・再送信しないようにする。
旧版に残る従来の同期データの表示挙動まで変更できるとは保証しない。
旧版が情報を落として再送信する場合や、旧版の閉鎖が新版へ伝わる場合を検証する。
具体的な形式と移行手順は設計書で扱い、混在利用の安全性を実証するまで一般提供しない。

## 5. 補完設計方針

以下は機能要件を実装可能にするための推奨案である。

| ID | 推奨する扱い |
| --- | --- |
| D-01 | 初回の同名判定は名前の完全一致とし、曖昧一致・大文字小文字変換・空白除去による自動統合は行わない。色・アイコンは候補の識別に使う |
| D-02 | 既存コンテナを再利用する場合、その端末の名前・色・アイコンを上書きしない。同期元の外観情報は候補表示と新規作成に使う |
| D-03 | 対応表をアカウントとプロフィールに紐付ける。アカウント変更で旧アカウントの関連付けを継承せず、実際のコンテナや Cookie は維持する |
| D-04 | ローカル ID が再利用されても、削除済みコンテナへの関連付けを復活させない。同名の別コンテナが後から作られても、再設定を待つ |
| D-05 | 初期実装の作成用メタデータは、同期定義を初めて作った時点の名前・色・アイコンを保持する。ローカル改名を全端末の外観更新として送らないため、新しい端末では初期の名前が候補・作成に使われる場合がある |

組み込みコンテナの翻訳名や、未対応の色・アイコン値の扱いは実装設計で定める。
利用できないコンテナ情報を受信した場合は、異なる所属での展開より保留を優先する。

## 6. 主な利用フロー

### 既存のログイン状態を使う

1. PC A の「開発」ワークスペースが、同期コンテナ「仕事」を参照する。
2. PC B が受信し、既存の「仕事」を候補として表示する。
3. ユーザーが関連付けを確認する。
4. PC B の「仕事」で受信タブを開き、その端末のログイン状態を利用する。
5. 以後は記憶した対応を使う。ローカルの表示名が変わっても再確認しない。

### 初回に同名コンテナがない

1. PC B が「仕事」を参照するワークスペース・タブを受信する。
2. PC B に同名候補がなく、初回未関連付けであることを確認する。
3. 名前・色・アイコンからコンテナを作成し、対応を保存する。
4. 受信タブを開く。ユーザーは必要なサイトにログインする。

### 関連付け先を削除した

1. PC B のコンテナ削除を検知し、関連付けと影響する同期タブを記録する。
2. その削除に伴う閉鎖を送信対象から除外し、削除後の関連付け保留を表示する。
3. PC A ではコンテナとタブを維持する。
4. PC B で再関連付けまたは新規作成を行い、現在有効な保留タブを開く。

## 7. 受け入れ条件

これらは実装後に検証する条件であり、本書作成時点のテスト結果ではない。

| ID | 条件 |
| --- | --- |
| AC-01 | 端末内のコンテナ番号が異なる二端末で、正しい対応先にタブが作成される |
| AC-02 | 同名候補が一件なら初回確認、複数なら選択となり、未確定では対象タブの読み込みが始まらない |
| AC-03 | 初回に候補がない場合は名前・色・アイコンを使って一度だけ作成され、再受信・再起動で重複しない |
| AC-04 | 関連付け後の名前変更でも同じコンテナを使い、複数ウィンドウ・ワークスペースで対応を共有する |
| AC-05 | ワークスペース既定とタブ個別指定を再現し、明示的な「コンテナなし」を既定コンテナで上書きしない |
| AC-06 | 既定変更で既存タブを自動再作成しない。明示操作でのみ選択した既存タブへ適用できる |
| AC-07 | 再利用時に既存の Cookie とサイトデータが維持され、同期ペイロードに認証情報が含まれない |
| AC-08 | 関連付け先削除後は自動再作成・通常コンテナへの展開を行わず、復旧操作を表示する |
| AC-09 | 削除に伴うタブ閉鎖が他端末へ伝わらず、再起動・再接続・遅延キャプチャでも削除が送信されない |
| AC-10 | コンテナ削除中に発生した無関係な通常のタブ閉鎖は、従来どおり同期される |
| AC-11 | 保留中に他端末で閉じたタブは、関連付け復旧時に開き直されない |
| AC-12 | 同期解除やワークスペース削除で、共有するコンテナ・Cookie・他ワークスペースの状態を消さない |
| AC-13 | 作成失敗・不正な受信情報・保存失敗時に誤ったコンテナで開かず、原因と再試行方法を示す |
| AC-14 | アカウント変更・サインアウト後に、旧アカウントの関連付けや遅延処理が新アカウントへ流用されない |
| AC-15 | 旧版との混在・アップグレード・ロールバックで誤所属とデータ消失が起きないことを検証できる |
| AC-16 | 英語・日本語、キーボード操作、複数ウィンドウで状態表示と復旧操作が利用できる |
