## 1. 目的、確定範囲、読み方

新しいタブから、日常的に使うサイトと購読した情報へ素早くアクセスできるようにする。既存機能・背景・利用者のデータを引き継ぎ、設定を Floorp Hub に集約する。

- **合意済み**: この会話で確認した製品方針と、入れ子フォルダーまで追加した操作プロトタイプの基本デザイン。
- **製品要件**: 通常操作・例外時の振る舞いを要件 ID で定める。要件が書かれているだけで検証済みとは扱わない。
- **採用した実装判断**: 実装時に確定した数値・保存方式・境界を §10 に記録する。会話でユーザーが個別に数値を承認したという意味ではない。
- **外部条件待ち**: 広告配信元など、このリポジトリと会話だけでは決められない契約情報。

基本機能の本体コード・共有 API・保存サービスを追加した。検証結果は QA レポート、未実測の性能・OS と追加広告配信の条件は §10 を参照する。未定の外部契約や未実施の確認を完了扱いにしない。

今回の対象はホーム、Speed Dial、RSS リーダー、Hub の新しいタブ設定、Places とワークスペースとの連動、既存設定・ピン留めの移行。
元サイトからの記事本文抽出は将来も含めて対象外。RSS 独自の端末間同期、OPML、JSON Feed 等は今回の前提に含めない（D-01 / D-10）。
プロトタイプの「前回のつづき・3タブ」は固定デモであり、既存機能や今回必須の製品機能とみなさない。導入する場合はセッション復元を別途設計する。

## 2. 用語とデータの共有範囲

| 用語・状態 | 意味・共有範囲 |
| --- | --- |
| Speed Dial 専用ルート | Places のブックマークフォルダー。配下を本機能の管理対象とする |
| グループ | 専用ルート直下のフォルダー。ワークスペースに割り当てる入口 |
| フォルダー | グループ内の任意階層の通常の Places フォルダー |
| グループ割り当て | ワークスペース ID とグループ GUID の対応。プロファイル内の同じワークスペースで共通 |
| 現在のワークスペース | ブラウザーウィンドウごとの状態。別ウィンドウの選択に追従させない |
| 現在閲覧中のフォルダー | 新しいタブの画面・履歴に属する状態。割り当て設定を自動上書きしない |
| RSS の購読・既読・スター | 同じ通常プロファイル内で共通。ワークスペースごとに分割しない |
| スポンサーの表示・個別非表示 | 同じ通常プロファイル内で共通。掲載内容もワークスペース共通 |

Places GUID をフォルダー・サイトの識別に用いる。表示名や URL だけを識別子にしない。独自のブックマーク複製データを別の正本にしない。

## 4. Speed Dial、入れ子フォルダー、ワークスペース

| ID | 要件 |
| --- | --- |
| SD-01 | 初期化で専用ルートと「共通」グループを用意する。プロトタイプの4グループや3ワークスペースを製品に自動作成しない |
| SD-02 | グループ内にサイトとフォルダーを混在させ、フォルダー内へさらにフォルダーを作れる。独自の固定の階層数制限を設けない |
| SD-03 | 作成・名前変更・サイトの URL 編集・保存先選択・移動・削除を Places に反映する。既存ブックマーク管理からの操作も観測する |
| SD-04 | 表示順の正本は Places の順序。ドラッグとメニューの前後移動を提供し、サイト・フォルダーを混在して並べ替える |
| SD-05 | パンくずで入口と祖先を示し、祖先へ直接戻る操作と「一つ上へ」を提供。長い名前・深い階層でも全画面を横に溢れさせない |
| SD-06 | 移動先は有効な管理対象フォルダーのみ。フォルダーを自分自身・子孫へ移して循環を作る操作は UI とサービスの両方で拒否する |
| SD-07 | フォルダー削除では配下サイト数・子フォルダー数と削除対象を示し、キャンセルを初期フォーカスとする。キャンセルでは一切変更しない |
| SD-08 | 同じグループを複数のワークスペースへ割り当て可能。新規ワークスペースは「共通」。切り替え時は割当グループの入口へ戻る。RSS・広告状態を初期化しない |
| SD-09 | 外部の名前変更・移動・削除・Places Sync・復元を画面へ反映。現在フォルダーがなくなったら最も近い有効な祖先、次に入口へ戻す。割当グループがなくなったら「共通」へ戻して通知する。「共通」もない場合は復旧用の空の入口を表示し、明示操作で再作成する |
| SD-10 | ワークスペースの削除は割り当てだけを解除し、共有ブックマークを削除しない。区切り・未対応ノードは表示対象外でも削除や変換をしない |

グループに指定できるのは専用ルート直下のフォルダー。グループを別グループ内へ移した場合は通常の入れ子フォルダーになり、従来の割り当ては SD-09 に従う。
グループの作成・名前変更・削除は新しいタブと既存ブックマーク管理から利用する。削除済み WS/group の対応は表示の有効な入口から除外し、次の割り当て保存時に古い対応を除去する。新たに失効した保存先を選ぶ操作は競合として再確認する。

同名フォルダーをルートと推測して乗っ取らない。GUID と管理メタデータでルートを発見し、Sync 初期化や復元で同名・複数候補になった場合は非破壊で解決する。
専用ルートが意図して削除された後に、完了済みの旧ピン留め移行を再実行して復活させない。新規の空の入口の回復と、古いデータの再移行を区別する。
リンクはブラウザー標準の同じタブ・修飾キー・中クリック・コンテキストメニュー操作を損なわない。

## 5. RSS と専用リーダー

### 5.1 必須の製品方針

| ID | 要件 |
| --- | --- |
| RSS-01 | 購読先はユーザーが追加する。新規利用者にサンプルフィードを自動購読させない |
| RSS-02 | ホームで新着を確認し、専用リーダーで読む。購読先・既読・スターは通常プロファイル共通 |
| RSS-03 | フィードに配信された本文を表示する。全文配信なら全文、抜粋なら抜粋。元サイトから追加取得・本文抽出する機能は将来も設けない |
| RSS-04 | 有効な記事 URL があれば「元サイトで開く」、なければ有効な配信元サイト URL を用意。両方なければ理由を示して無効にする。本文がなければその旨を示し、内容や URL を捏造しない |
| RSS-05 | 記事を実際に開く操作で既読にする。一覧に現れただけでは既読にしない。既読・未読への変更、スターの付け外しを提供する |
| RSS-06 | 同じフィードの再取得で記事を重複追加せず、本文更新で既読・スターを失わない。別フィードの記事を URL 一致だけで勝手に統合しない |
| RSS-07 | 自動・手動更新、最後の成功時刻、更新中・失敗・オフライン状態を表現し、失敗しても最後の成功データを読める |
| RSS-08 | フィードの本文・タイトル・リンクは外部の信頼できない入力として扱う。特権付き新しいタブのスクリプトや機能を起動させない |
| RSS-09 | 購読解除では取得を止める。スター付き記事の保持と非スターの削除範囲を確認表示し、記事保管の操作を明確にする（詳細は D-03） |
| RSS-10 | フィード・記事・既読・スターの保存と更新をタブ数に依存させず、複数タブの操作を一貫して反映する |

### 5.2 採用した取得・正規化（D-01 / D-02）

- RSS 2.0 と Atom 1.0 に対応する。RSS 1.0 / JSON Feed / OPML は対象外で、未対応形式は失敗として通知する。
- HTTP(S) のフィード URL を入力して検証する。HTML が返った場合は rel=alternate の RSS/Atom 候補を示してユーザーが選ぶ。これはフィード発見であり本文抽出ではない。
- URL はフラグメント除去等の必要な正規化に留め、query を並べ替えたり勝手に削除したりしない。複数候補を黙って全購読しない。
- 記事 ID は feedId と guid / Atom id、欠落時は記事リンク、さらに欠落時はタイトル・日時等の安定ハッシュを使う。本文の変更だけで ID を変えない。
- RSS は content:encoded を優先し、なければ description。Atom は content、なければ summary。外部 URL を指す content は取りに行かず、元サイトへ案内する。
- 相対 URL は feed の基準 URL / xml:base に従って解決してから検証する。UTF-8 以外、日付欠落・不正日付、名前空間をテストする。
- 初回に取り込む記事は未読。記事一覧は有効な配信日時の降順、日時欠落は初回検出時刻、同時刻は安定 ID で順序を固定する。
- 定期更新はブラウザー稼働中のプロファイル単位で行い、タブを開くたびに無条件で取得しない。オフライン・終了・スリープ復帰で大量の取り戻し取得をしない。
- ETag / Last-Modified、304、429 と Retry-After を扱う。手動更新でもサーバーの Retry-After を尊重する。タイムアウト・形式不正・過大応答でも成功キャッシュを置き換えない。採用した数値は §10 を参照する。
- 取得に通常閲覧の Cookie・認証情報を添付しない。各リダイレクト先を検証し、その URL 自身の content principal で新しい匿名 channel を開く。全 hop 合計20秒・最大5回で制限する。ログにトークン付き URL や本文を出さない。認証が必要なフィードは対象外。

### 5.3 採用した保持・本文表示（D-03 / D-04 / D-05）

- 非スターの記事は初回検出から既定90日、かつ1フィード最大500件とする。古いものから整理し、スターは両制限から除外する。Hub に保持範囲を示す。
- キャッシュ整理後の再配信で既読記事が新着へ戻らないように tombstone を保持する。tombstone は365日・10万件まで、DB 本体は100MiBまでとした。WAL を含むプロファイル全体の容量保証や性能実測とは区別し、無制限のスター保存を保証しない。
- 購読解除は通信を止め、非スターのキャッシュを削除し、スターと表示に必要な出典・本文を「購読解除済み」として残す。再購読は同じ feedId と既存状態を利用する。解除済みのスターを外すとその記事本文を削除する。全保存データの一括削除 UI は今回追加していない。
- 本文は許可した AST で描画し、生 HTML を特権 DOM へ挿入しない。外部画像は既定で自動取得せず、各画像の明示操作で匿名取得・検証して表示する。外部 CSS・フォント・動画・iframe・フォーム・スクリプトを実行・自動取得しない。
- フィード URL やリンクの許可スキームは HTTP(S)。javascript / file / chrome 等を実行しない。ブラウザーの通常の証明書・プロキシ・接続制御を尊重する。
- プライベートでは標準の about:privatebrowsing を維持する。新しいタブ/フィード/Hub の本機能を明示的に開いても、通常プロファイルの個人データ（ブックマーク・背景・RSS）とスポンサーを返さない。親 actor が DB open・移行・scheduler 開始より前に拒否し、空の private snapshot 以外の要求は READ_ONLY とする。

## 6. スポンサー

| ID | 要件 |
| --- | --- |
| SP-01 | ユーザーのサイトとは別に固定2枠を用意し、各タイルへ「スポンサー」と明示する。ユーザー登録サイトの枠を削除・置換しない |
| SP-02 | 掲載内容は全ワークスペース共通。新規の表示設定は有効。Hub で全体を非表示にでき、各タイルでも個別に非表示にできる。操作は Firefox に合わせる |
| SP-03 | 全体設定と個別非表示を再起動後も保持し、配信 revision・ワークスペース・閲覧階層の変更で初期化しない |
| SP-04 | 「自分の Speed Dial に保存」は、その時点の名前・URL を閲覧中フォルダーの通常のブックマークとして保存する。その後の広告変更や非表示で書き換え・削除しない |
| SP-05 | 取得失敗・期限切れ・不正な配信・未配信を通常のサイト利用の障害にしない。広告の仮データや空の広告ダミータイルを本番に出さない |

2枠は掲載できる枠数を指す。有効な掲載が2件あり除外がなければ2件、個別非表示・未配信時は空のタイルを残さない。同じ2枠を各フォルダーでも共通表示する。
安定した sponsorId を使用し、非表示の単位が変更される場合は選択を維持する設計を先に定める。
同じ保存先への同 URL の保存は既存のブックマークを返し、勝手に増やさない。表示した名前・URL と掲載が変わった場合は競合として再読み込みを促す。旧ピン留めにある同 URL のサイトを広告と推測して削除しない。
現在は既存 Cubesoft 1件を同梱し、pref floorp.newtab.sponsorCatalog のカタログで最大2枠を選ぶ。新しい remote endpoint・素材配信・クリック/表示計測・個人化は追加していない。追加の配信元・素材・ID 運用は外部条件（D-08）。

## 7. Hub と既存機能の継承

| ID | 要件 |
| --- | --- |
| HUB-01 | 今回から新しいタブの設定を Hub に集約。歯車は about:hub#/features/newtab へ移動する。独立した新タブ設定ドロワーを残さない |
| HUB-02 | サブ項目は表示とレイアウト / Speed Dial / フィード / スポンサー。背景・スライドショー・割り当て・表示・保持方針等を整理する |
| HUB-03 | Hub と開いている新しいタブで同じ設定を参照し、保存完了後に他画面へ反映する。競合時に別画面の設定を黙って上書きしない |
| HUB-04 | 設定検索・項目への直接移動・日本語/英語翻訳を追加する。既存の Floorp Start 無効化設定は同じ値を使い、二重管理しない |

サイト・フォルダーの整理、購読追加・解除、既読・スター、スポンサー個別非表示は作業している画面に残す。Hub への集約は日常操作まで全部移す意味ではない。

| 既存機能 | 必ず維持する内容 |
| --- | --- |
| 背景5方式 | なし / 内蔵ランダム / 自分の画像 / 指定フォルダー / Floorp 画像。選択値、画像、ファイル名、パスを保持 |
| 既存画像 | 内蔵100枚、Floorp6枚。プロトタイプの写真3枚は容量削減用サンプルであり製品の上限にしない |
| スライドショー | ランダム・フォルダー対象、秒間隔、画像間フェード。新規は無効・30秒、既存は値を継承 |
| 時計 | 現在時刻、地域に応じた曜日・月日、表示切り替え |
| 検索 | 表示切り替え、URL バーへのフォーカス。既定検索・プライベート設定をブラウザー側で扱う |
| よく使うサイト | 履歴候補、少数時の既存候補、ピン留め相当操作、URL 単位非表示と Hub からの復元。Speed Dial と別の領域・データとして維持 |
| 配置 | 旧2種類の配置選択を保持し、新しいホームの3配置とは別に扱う |
| Floorp Start 無効化 | floorp.design.configs の同じ値を Hub 新タブ設定へ移し、再起動後に Firefox 標準へ戻す。外観設定にはリンクを残す |
| 言語・テーマ・リンク | ブラウザー言語、システムテーマ、通常のリンク操作 |

履歴候補を自動的にブックマークに変換しない。旧 components.topSites=false は Speed Dial と履歴候補の両方の新規表示設定を非表示にする。履歴候補からの保存は通常の Speed Dial ブックマーク作成を使い、URL 単位の非表示と Hub の復元は別に保持する。

## 8. データ移行と障害時

| ID | 要件 |
| --- | --- |
| MIG-01 | floorp.newtab.configs の raw と pinned を移行 journal に先行保存する。関連する既存設定の値を維持し、解釈不能・保存失敗で初期値に上書きしない |
| MIG-02 | 背景・表示・検索・blocked・旧配置・Floorp Start 無効化を保持し、新設項目だけに既定値を補う |
| MIG-03 | 全ピン留めを名前・URL・順序を保って「共通」へ一度だけ移行する。URL や名称だけで広告由来と判定して除外しない |
| MIG-04 | バージョンと項目ごとの移行記録を持ち、途中終了・再起動・複数ウィンドウ・再実行で重複や欠落を生まない。既存の同名フォルダーを上書きしない |
| MIG-05 | 復帰時に移行後のユーザー編集や既存ルートを一括削除しない。Firefox 標準への無効化と、対応コミット revert/対応版変更による旧 UI への復帰を区別する。旧 UI 選択の feature gate は追加していない |

設定競合、Places 一時停止、DB のロック/破損、画像ファイルの消失、フィード失敗を区別し、通常のサイト操作を可能な範囲で継続する。
保存失敗では成功扱いにせず、再試行・修復の入口を示す。未取得と空データを混同してルートや購読を作り直さない。
