## 実装した構成

- 新しいタブは中央検索、時計、ホームの要約、Speed Dial と入れ子フォルダー、専用 RSS リーダーを備える。既存の背景5方式、内蔵100枚・Floorp6枚、スライドショー、旧2配置・表示設定を引き継ぐ。
- Speed Dial は通常の Places ブックマークを正本とする。専用ルートの直下フォルダーがグループとなり、ワークスペース割り当ては共有、現在のワークスペースは呼び出し元ウィンドウから取得する。
- RSS 2.0 / Atom 1.0 と HTML のフィード候補選択に対応する。配信された本文だけを表示し、元サイトからの追加全文抽出は将来も対象外。
- New Tab と Hub は `libs/newtab` の型付きクライアント、`NRNewTab` actor、親プロセスの各サービスを共有する。設定の比較更新と変更通知を使い、タブごとに取得ジョブや独自の永続データを持たない。
- Hub の `about:hub#/features/newtab` に表示・背景・割り当て・RSS 更新間隔・スポンサー設定を集約する。Floorp Start 無効化は既存の設定値を移設し、外観設定からリンクする。

## 設計時の案から確定した判断

| 項目 | 現在の実装 |
| --- | --- |
| 設定 | `floorp.newtab.configs`、schema 1。未知キーと旧値を保持し、revision を照合して保存 |
| RSS 保存 | `<profile>/floorp/feeds.sqlite`、schema 2。既読・スターは記事に保存し、整理後の既読は tombstone に保持 |
| RSS 取得 | 既定15分、選択0/15/30/60分。並列4、開始 URL の origin ごと2、全リダイレクトを通じて20秒、展開後5MiB、最大5リダイレクト |
| 本文・画像 | 許可した AST を React で表示。外部画像は各画像の明示操作で匿名取得。各取得 hop の URL 自身の principal で新しい channel を作る |
| 保持 | 非スター既定90日かつ500件/フィード、スター除外。DB 本体100MiB上限、tombstone365日・10万件上限 |
| private | 標準のプライベートページを維持。明示的に新タブ/Hub を開いても親 actor が本機能の個人データ取得・永続変更・移行を拒否 |
| 移行 | 生の旧設定を含む journal を先に保存し、GUID ごとに再開。完了後の修復は空の入口を作り、旧 pinned を再投入しない |
| スポンサー | 既存の Cubesoft 1件を同梱。pref カタログによる最大2枠に対応。新しい remote endpoint・計測は追加しない |

本文保持の上限は無制限なスター保存を保証しない。SQLite の上限は DB 本体に適用され、WAL を含むプロファイル全体の容量保証ではない。採用した上限と未実測の性能保証も区別する。

異なる開始 origin が同じリダイレクト先へ合流する場合、最終 origin の同時2件までは保証せず、全体4件の制限を保つ。

## 復帰手段と残る確認

旧 Floorp Start UI を選ぶ feature gate は実装していない。Hub の「Floorp Start を無効にする」は、再起動後に Firefox 標準の新しいタブへ戻す既存設定である。旧 Floorp Start UI へ戻すには対応コミットの revert または対応版への変更が必要であり、Places・RSS DB・移行 journal を自動削除する処理は追加していない。

実機 Windows/macOS、配布物全体、長時間動作・大規模データ・ぼかしの性能予算は、QA レポートに記録された範囲以外を成功扱いにしない。追加の本番広告配信先・素材・ID 運用は外部契約として別途必要になる。
