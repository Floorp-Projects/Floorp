# Isolated recipe

Scripts contain local Cloud paths, not credentials; adapt the one task root and product/sysroot paths for another isolated runner. Require Python marionette_driver, NSS certutil, Xvfb, Openbox, xdotool, task-owned loopback ports/private DBus. HTTPS_PROXY is read without logging; CA is imported only into new owned profiles. Do not source sandbox-disabling environment scripts.

1. Obtain official12.17.2,12.18.0 and12.21.1 archives and12.18.0 full MAR from Floorp release assets; verify published hashes/manifests saved in acquisition/. Extract to task products, copy12.17.2 into update-chain/install/floorp. Never point the updater at a shared prefix.
2. `dbus-run-session -- <venv-python> browser-session.py --product <task>/update-chain/install/floorp --out <task>/trials/old-seed-v2 --profile <task>/profiles/update-chain-v2 --display 230 --port 28986 --http-port 19186 --fixture none`. Read ready.json, use control.send for real keys/chrome observations and stop. Require shutdown exit0.
3. Copy shipped old updater/updater.ini to own updater-run directory and official MAR to own patch/update.mar. Hash-check. On private X display, set LD_LIBRARY_PATH to the **old owned product** and platform sysroots. Run `dbus-run-session -- <task>/update-chain/updater-run/updater 1 <task>/update-chain/patch <task>/update-chain/install/floorp <task>/update-chain/install/floorp first 0`. Keep normal update-settings.ini and protections. Native status must succeed; never manufacture status/history. Initial attempt missing mozsqlite is not an update result. Compare installed regular-file hashes against official12.18 archive.
4. Relaunch updated own install with same profile using --reuse-profile and --fixture none, fresh out=trials/mar-to18. Observe isUpdated=true and full version/build. Use real WebDriver element clicks on `button[data-variant=primary]` in about:welcome?releaseNotes=1, then inspect chrome state after the content tab closes. Run actual Ctrl+T/Ctrl+W. Stop normally; restart same profile again with fixture none to verify persistence.
5. Current controls use own official12.21.1 and independent profiles: fixture none; fixture update --display-version 12.21.1@159.0.1 --prior-version 12.18.0@156.0.1; fixture prompt --display-version 12.21.1@159.0.1. Use unique display/ports per live session. Fixtures are not genuine update evidence. Saved request JSON records actual commands.

control.send writes an atomic command.json; browser-session emits result-ID.json plus CPU samples. Await ready first, use unique command IDs, inspect all exceptions. A post-click NoSuchWindow is expected only when subsequent chrome state proves the welcome tab closed correctly; don't silently count an error as success. Stop requests use normal eAttemptQuit, and shutdown must say exitCode0 without forcedTermination. No long-soak claim from these short samples.
