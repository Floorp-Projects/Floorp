## Contract and plausible interaction

1. Floorp `updateTabsVisibility`, main source **386-429**, decides tab visibility only from `floorpWorkspaceId`. Missing/invalid workspace attribution is assigned to the current workspace. For every tab whose workspace ID equals the selected Workspace, it calls **`gBrowser.showTab(tab)` unconditionally (419-424)**, without checking who hid it. Other-workspace tabs are passed to `hideTab` without an extension source. Selecting an actual Workspace calls `setCurrentWorkspaceID` then `updateTabsVisibility` (local source761). A reactive effect also refreshes on selectedWorkspaceID (86-94). Merely enabling Workspaces or doing repeated STG group switches is a different trigger from actually switching Floorp Workspace away and back.
2. Runtime `Tabbrowser.sys.mjs` **7864-7879**: `showTab` returns for an already visible tab; otherwise it removes `hidden`, invalidates visible-tabs cache, dispatches `TabShow`, then deletes SessionStore custom tab value **`hiddenBy`**. This owner is a SessionStore value, **not a DOM attribute**. Runtime `ext-tabs.js` **1661-1665** passes `extension.id` to `hideTab`; STG-owned hidden tabs can therefore have `hiddenBy=simple-tab-groups@drive4ik`. Floorp's unconditional show can remove both their hidden state and ownership marker. The hypothesis is concrete but still needs the parent's runtime event trace to establish frequency/outcome.
3. Runtime `hideTab` **7894-7903** refuses already hidden, pinned, selected, closing, and active screen/microphone/camera-sharing tabs. Do not diagnose those documented exceptions as an arbitrary hide failure. Split views also propagate visibility to sibling tabs; use ordinary non-pinned/non-sharing/non-split fixture tabs for the minimal test.
4. STG `js/tabs.js` **638-678** wraps browser.tabs.show/hide, batching IDs and retrying one by one on an exception. `safeHide` **680-690** adds IDs to its `excludeTabIds`, awaits hide, then removes them. The exact helper uses browser APIs; no CSS-only hiding is involved.
5. STG `applyGroup`, `stg-background.js` **189-275**, guards re-entry with `_loadingGroupInWindow`. It **shows the incoming group's tabs first** (242-258, guarded by `excludeTabIds`), updates window→group association (266), then hides the outgoing group's tabs (269+). Consequently, an event-level interval with both groups visible is possible even on normal STG switching. This alone does not prove a final isolation failure or visible human-perceptible flicker.
6. STG `onUpdatedTab`, **500-590**, is not passive. It ignores its own `excludeTabIds`, recalculates changes against the cache, then handles external hidden/pinned changes. At **531-536**, `hidden:true` removes the cached STG group from that tab. At **548-563**, unexpected `hidden:false` for a tab with an STG group can call **`applyGroup(tab.windowId, tabGroupId, tab.id)`** if the current window group has tabs; other paths re-hide or reassign the tab. Its listener explicitly includes the HIDDEN property (`js/constants.js:359-366`, registration at2043). Thus actual Floorp Workspace hides/shows may cause STG reassociation/reactivation, not merely temporary exposure.

## Hypotheses for the already authorized product test

- **H1: owner override on Workspace return.** Keep STG groups A/B within the same Floorp Workspace W1; STG B inactive tabs are hidden. Switch Floorp W1→W2→W1. Observe whether Floorp shows every W1 tab including STG B and clears its `hiddenBy`, and whether STG then re-hides, reactivates B, or loses group association. Final state must be compared with STG's active group and per-tab session IDs.
- **H2: transition only.** Separate STG's expected show-new-before-hide-old sequence from external Workspace-driven shows. Preserve event order/timestamps, visible count after each event, and a settled final snapshot. A 1-event overlap without a frame or settled leak is not the reported persistent failure.
- **H3: external-hide feedback.** Moving W1 tabs out of view can be seen by STG as an external hide and clear association. On return, unhidden tabs may be adopted into the current STG group. Capture association before/after, not just tab.hidden.

These are source-backed hypotheses, not confirmed defects. Any eventual fix must preserve both Workspace isolation and STG hide ownership across Workspace transitions. Skipping all hidden tabs in showTab would also leave Workspace-owned hidden tabs stuck, so it is not a justified one-line solution.
