1. Download artifact13452071690 from Actions run42103462848. Verify the ZIP SHA256 against package-acquisition.json, extract floorp-linux-x86_64.tar.xz, verify its SHA256, and safely extract into a fresh product directory. The upstream Runtime/native source and exact dispatch inputs are recorded in runtime-contract.json and dispatch-inputs.json. The latter is a historical receipt, **not an instruction to dispatch another run**.
2. Install Marionette Python dependencies and Xvfb, xdotool, Openbox and DBus. run.py records the current isolated dependency paths; adjust those paths for the receiving machine, rather than editing product files. Require normal user namespaces/sandbox support and an unused private display117 plus HTTP29971/29972 and chosen Marionette port. Do not source an old sandbox-disabled environment file.
3. Run `python run.py /fresh/floorp/floorp 29981` in a new evidence directory/port. The normal run configures gestures through the current settings UI and performs24 primary checks before the6guards. To reproduce only guards after a fixture correction, run `python run.py /fresh/floorp/floorp 29983 guards`. To reproduce only the final remaining mismatch bottom guard, use `QA97_API_BOTTOM_ONLY=1 python run.py /fresh/floorp/floorp 29985 guards`. Existing run directories are intentionally rejected instead of overwritten.
4. Require live manifest BuildID agreement, target endpoint, all untargeted positions unchanged, focus qualification, no context-menu popup, normal product exit0 and complete unchanged payload manifests. A wrapper exit1/timeout/cleanup signal is not a passing run. Recorded partial29981 and pre-guard29982 are retained as harness-failure evidence; they are not whole-suite passes.

The two foreign-native-window-focus checks explicitly call the unmodified production action export with an actual target Window while a different real Window owns native frame focus. This is an API fixture for the otherwise difficult mismatched-focus guard, not a physical gesture on an inactive window. The four tab/window gesture guards use native OS input. HTTP query token values in evidence identify controlled fixture documents and are not credentials.

Original Windows11/HuggingFace, original profile and physical input remain separate conditions. The final product has no diagnostic module replacements. Browser profiles, binaries, signed download links and raw startup logs are intentionally not committed; small controlled-page screenshots, passive scroll records, error records and whole-payload hash manifests are included.
