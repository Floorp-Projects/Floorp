# KAN-71 follow-up: real GUI startup activation

Source main remains `984509d2053be7bae9027133bda7259cd706b208` (latest main rechecked). Official Floorp12.21.1 / Gecko159.0.1 Runtime build20261103153232 and Firefox159.0.1 build20261102144711; fresh isolated profiles, content sandbox6, TLS verification retained. No KAN-20/21 network retests.

## Independent real GTK application and actual timestamps

`gui_link.py` is a separate native GTK3 application with a real `Gtk.LinkButton`. A synthetic XTest pointer click activates the **default GTK link handler**, which launches the configured desktop entry through GTK/GIO. No startup ID or timestamp is fabricated or injected by the test. The GUI logs its actual GDK button-release timestamp. `desktop_launcher.py` records only whether GTK/GIO supplied DESKTOP_STARTUP_ID / XDG_ACTIVATION_TOKEN and the numeric `_TIME` suffix of the generated startup ID, then execs the target official browser with the isolated profile. The complete ID/token strings are never logged.

`startup_monitor.py` listens to actual X11 root `_NET_STARTUP_INFO_BEGIN` / `_NET_STARTUP_INFO` ClientMessages. It saves `new`/`remove` and numeric timestamp only. Each successful trial has a nonzero GDK event timestamp, generated startup ID timestamp, and an actual X11 **new** message with that same startup timestamp. The launch environment also contains an activation-token variable, but these are X11 runs: this is not evidence of Wayland activation-protocol execution.

The browser was already running. No browser window-activation call occurs after the link click. The source GUI is activated before the click; `_NET_ACTIVE_WINDOW` is measured before and five seconds after, and compared with visible browser window IDs. A local HTTP fixture independently records URL receipt. The original parent PID is obtained through the same Marionette session before and after.

## Cinnamon environment and limits

Downloaded Debian Cinnamon packages into an isolated sysroot (210MB dependencies), preserving the vendor `cinnamon.session` required components. The original wrapper's absolute `/usr/lib/.../cinnamon-session-binary` path and extracted desktop/service Exec paths were relocated to that same extracted sysroot. Missing Muffin/Clutter/Keybinder type-library search paths were corrected from observed startup failures; session autostarts were loaded rather than removed. No window-manager focus prevention, startup checks, security checks, session component requirements or product sandbox were disabled.

The real Cinnamon session manager reached RUNNING, `org.Cinnamon` acquired its owner, and the shell logged `Cinnamon took ... to start`; the real panel, menu, Nemo and window-management UI were visible. This is stronger than standalone Muffin or Xvfb alone. **It is Debian13.6/Xvfb with a user-space Cinnamon session, not Linux Mint's normal login session.** The host has no usable system bus/logind/NetworkManager/RealtimeKit services; auxiliary calendar/power/network services produced setup errors. No claim of a fully equivalent native Mint desktop, KDE or Wayland is made. Physical input is not required by the coordinating user; synthetic GUI input and actual timestamps were measured explicitly.

## Classification and remaining condition

Substitute-environment symptom reproduced in both products, **no confirmed Floorp-only defect**. Remaining: native Mint/Cinnamon session with its ordinary desktop/system services and a matched Firefox control demonstrating the reported contrast, plus observation of which browser/WM activation stage differs if it does. No speculative forced-focus fix or Draft PR is justified by equal behavior.

One initial pointer coordinate missed the link: no GUI event, launch or GET occurred. It is retained locally as `missed-link-harness.json`, excluded from the eight-trial product count. Startup failures while relocating the Cinnamon sysroot are also infrastructure setup evidence, not product failures.

Run `dbus-run-session -- <marionette-python> run_activation.py floorp muffin` (then Firefox), or use desktop argument `cinnamon`. Dependencies and isolated paths are explicit in the script. Exported small observation JSON contains the actual event/startup timestamps, X11 message kinds, parent PIDs, active/browser window IDs and GET booleans, allowing independent recomputation. Screenshots and complete session logs remain local; no profile, cookie, private URL or complete activation token is exported.
