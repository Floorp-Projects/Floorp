## Readiness symptom versus allocation cause

Native [NewSession](source/runtime-c74/remote/marionette/driver.sys.mjs#L2676) waits browserStartupFinished, resolved on browser-idle-startup-tasks-finished ([Marionette](source/runtime-c74/remote/components/Marionette.sys.mjs#L221)). pageLoadStrategy:none cannot bypass this startup gate. A stuck native/privileged initialization path can therefore explain the RPC timeout without making RPC the allocator.

Native157 DocumentL10n144–185 lacks error checks immediately after TranslateRoots and Promise::All. Readonly native159 diff adds those checks and ScopeExit failure completion (native157-159-readonly-comparison.patch). This is a concrete readiness-hardening difference, **not evidence those error branches occurred or that it causes12GiB**, and not a proposed157→159 change. I18nUtils/config/overlay bytes remain the same in observed Floorp main29a.

## One useful next observation — not executed here

The proposed clean exact-parent English normal-quit bootstrap + preRTL snapshot removes the strongest profile-history confound. Before increasing the memory ceiling or trying more UI conditions, classify main-process memory while still small: one non-minimizing native memory report can separate chrome/privileged JS and DOM/window objects from Fluent/native heap, layout/style, or graphics/font allocations. Raw report object counts/compartment URLs also distinguish session/page proliferation. A short independent native/JS stack sample can localize a busy main thread if the report cannot run.

Exact c74 [nsMemoryInfoDumper](source/runtime-c74/xpcom/base/nsMemoryInfoDumper.cpp#L131) documents SIGRTMIN for ordinary reports; Initialize242–253 registers it only under MOZ_SUPPORTS_RT_SIGNALS. Establish handler registration before signaling; never assume availability from source alone. Avoid SIGRTMIN+1 (minimization changes the phenomenon) and avoid treating absence of a report as absence of a leak: the signal dispatches work to the main thread, which may already be blocked. Root owns any bounded capture decision; no signal/process launch/capture was issued here.

This supports a bounded fresh-parent capture at early startup, not a speculative product patch, source test rerun, larger resource allowance, or full RTL PASS. Root cause remains unconfirmed.
